# TTS Player — пауза других плееров вместо приглушения

**Статус:** в работе — обсуждение идёт.

## Задача

Пока плеер говорит, другие плееры (Chrome, Firefox, Spotify…) стоят на паузе, а не звучат
тише; когда замолкает — продолжают. Приглушение громкости чужих потоков (`ducking.py`,
настройка `duck`, `duck.json`, `duck-orphans.json`) убирается целиком.

Причина (2026-10-11): громкость Chrome залипла на 35 % — WirePlumber запоминает громкость за
приложением, в том числе сниженную плеером, а у Chrome поток живёт, только пока играет звук;
механизм «сирот» этого не покрыл. Пауза не меняет ничего, что система запоминает.

## Решения

Согласовано (со слов пользователя, 2026-10-11):
- Пауза через MPRIS (D-Bus `org.mpris.MediaPlayer2.Player`) вместо приглушения.
- Приглушение убирается целиком: `tts_player/ducking.py`, `Ducker` в `__main__.py` и `Player`,
  поле «Приглушать другие звуки до, %» на экране настроек, ключ `duck` в `settings.json`,
  раздел README «Приглушение чужих звуков», контракт (9) спеки настроек.
- WirePlumber не обновляется: в репозиториях Mint 22.3 (noble) только 0.4.17; приглушение по
  ролям из 0.5 — отдельная задача, если понадобится.
- Пауза включается флажком на экране настроек «Ставить другие плееры на паузу, пока говорю»
  на месте поля приглушения; по умолчанию включён. Пишется той же кнопкой «Сохранить», что и
  хвост. Снят — другие плееры не трогаются (музыка фоном под озвучку).
- Действие пользователя главнее паузы плеера. Пользователь сам запустил поставленный на паузу
  плеер во время речи — плеер его больше не трогает до следующего начала речи. По окончании
  речи продолжаются только те, кто всё ещё стоит на паузе, поставленной плеером; остановленный
  (Stopped) или исчезнувший с шины не продолжается.
- Пауза ставится один раз — в момент начала речи. Плеер, заигравший во время речи (новое
  видео, следующий трек, автовоспроизведение сайта), не трогается.
- Пауза снимается после 5 с тишины плеера, а не сразу: между сообщениями одного хода Claude
  видео не дёргается. Речь началась снова до истечения 5 с — запомненные остаются на паузе,
  новой паузы никому не ставится. Длинный вызов инструмента (> 5 с) паузу разрывает — цена.
  Задержка — постоянная в коде, не настройка.
- 3 с тишины между паузой других плееров и первым словом — только если хоть один плеер был
  поставлен на паузу. Зачем: после видео нужно время переключить внимание на озвучку; сразу
  без паузы начало речи пропадает. Ничего не играло — речь начинается сразу. В конце паузу
  даёт задержка 5 с перед продолжением (пункт выше).
- В эти 3 с окно выглядит как при игре: на кнопке ⏸, строка сообщения выделена, ползунок на
  0:00, звука нет; отсчёта не видно. Команды работают как обычно: ⏸ — звук так и не
  начнётся, через 5 с другие плееры продолжат; «следующее» или клик по другой строке —
  выбранное начнётся по истечении тех же 3 с (отсчёт не перезапускается: другие уже стоят).

Записано мной, не разобрано:
- Когда ставить на паузу — там же, где сейчас приглушение: плеер звучит для других
  (`Player._speaking`: статус playing, включая ожидание предложения растущего сообщения, или
  удержание ради своего текста), решает `_follow_status`.
- Флажок снят и сохранён, пока другие стоят на паузе, — запомненные продолжаются сразу; флажок
  поставлен во время речи — пауза ставится со следующего начала речи.
- Вызовы D-Bus асинхронные (Gio), с таймаутом 1 с: зависший плеер не останавливает главный
  цикл. Pause() не прошёл (ошибка, таймаут) — плеер не запоминается и в расчёт 3 с не идёт;
  ошибка — строка в stderr. 3 с отсчитываются от первого прошедшего Pause().
- Старый ключ `duck` в `settings.json` при чтении игнорируется, при «Сохранить» не пишется
  (пишутся все известные ключи). `duck.json` / `duck-orphans.json` новый плеер не читает и не
  удаляет: они в `$XDG_RUNTIME_DIR` и уходят с выходом из сеанса; сейчас их нет, а старый
  плеер при выходе громкости возвращает сам (`restore`).
- Спека настроек 2026-10-09 реализована, поэтому в ней меняется только строка «Статус»:
  контракт (9) заменён этой спекой; описание ключа `duck` в контракте (6) там остаётся
  историей.

## Цепочка

```
Player._follow_status ──(начал звучать / замолчал)──▶ пауза других плееров
пауза других плееров ──D-Bus, сессионная шина──▶ MPRIS-плееры (org.mpris.MediaPlayer2.*)
экран настроек ──settings.json (контракт (6))──▶ Player
```

## Контракты

### (9') Плеер → MPRIS-плееры: пауза на время речи

```
список     org.freedesktop.DBus.ListNames → имена с префиксом org.mpris.MediaPlayer2.
статус     org.freedesktop.DBus.Properties.Get("org.mpris.MediaPlayer2.Player", "PlaybackStatus")
           → "Playing" | "Paused" | "Stopped"
начало     каждому с "Playing" → org.mpris.MediaPlayer2.Player.Pause(); имя запомнить
           хоть один Pause() прошёл → звук плеера начинается через 3 с; ни одного — сразу
во время   запомненный стал "Playing" (пользователь запустил сам) или "Stopped", или его имя
           ушло с шины (NameOwnerChanged) → забыть; отслеживание — сигнал
           org.freedesktop.DBus.Properties.PropertiesChanged на /org/mpris/MediaPlayer2
           (моё: забыть сразу, иначе «запустил и снова поставил на паузу сам» продолжилось бы)
конец      плеер замолчал → через 5 с, если речь не началась снова: каждому запомненному, чей
           PlaybackStatus сейчас "Paused" → Player.Play(); список очищен
           выход плеера → сразу, без задержки
след       в файлы не пишется; падение плеера оставляет других на паузе
```

### (6) settings.json плеера

```
было   {"tail": <целое 1–20>, "duck": <целое 0–100>, "autoplay": <true|false>}
стало  {"tail": <целое 1–20>, "autoplay": <true|false>, "pause_others": <true|false>}
нет ключа / не true|false → pause_others = true, строка в stderr (как autoplay)
имя ключа — моё: по образцу соседей, «pause» один спутался бы с паузой самого плеера
```

## Открытые вопросы

- Chrome держит один MPRIS-объект на браузер и управляет медиа одной вкладки; если видео
  играет в двух вкладках, Pause() остановит, вероятно, только одну — проверить на живом
  Chrome при реализации: от этого зависит, хватит ли MPRIS для основного случая.
- Плееры, отвечающие `CanPause = false` (прямые эфиры у части сайтов), — Pause() им не
  поможет; звучат дальше. Отдельной обработки не предлагаю, пока не встретится.
