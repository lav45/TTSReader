# TTS Player — несколько озвучиваемых сессий

**Статус:** карта согласована 2026-10-09; план — после реализации спеки кэша. Реализуется после спеки кэша `2026-10-09-tts-player-text-cache-design.md` — опирается на её цепочку (11)–(13).

## Задача

Сейчас озвучивается одна сессия Claude Code — последняя, где вызван `/tts-on` (флаг
`/tmp/claude-tts.on`). Нужно: плеер ведёт список активных сессий; каждая собирает свои
озвученные сообщения; играет только выбранная сессия.

## Решения

Со слов пользователя, 2026-10-09:
- `/tts-on` передаёт текущую сессию плееру, плеер добавляет её в список активных сессий.
- Список сессий — на главном экране между рядом кнопок управления и списком воспроизведения.
- Строка сессии: ID; справа — кнопка завершения сессии (то же, что `/tts-off` из чата) и кнопка
  очистки.
- При завершении сессии все её файлы из её истории можно удалить.
- Клик по сессии делает её активной.
- Хук озвучки берёт ID сессии не из файла-флага, а спрашивает у плеера.
- Озвученные файлы попадают в список своей сессии.
- Проигрывается только активная сессия; остальные только собирают файлы в свой список.
- Синтезируется только активная сессия (2026-10-09, выбрано из: все / только активная /
  все, активная первой). Причина выбора — демон говорит очередь по одному сообщению, и
  ответ неактивной сессии задерживал бы речь активной.
- Неактивная сессия собирает текст ответов (задачи хука, контракт (11) спеки кэша); звук
  синтезируется, когда сессия стала активной и до сообщения дошло воспроизведение — тем же
  путём, что переозвучка устаревшего кэша (2026-10-09, моя рекомендация, принята).
- ID сессии — UUID сессии Claude Code; строка списка — «проект · первые 8 знаков UUID»
  (`TTSReader · 1dd2b064`), проект — последний компонент `cwd` сессии. Гейт передаёт хуку
  `CLAUDE_TTS_SESSION=<UUID>`; настройки `claude-tts` уровня сессии ведутся по UUID
  (2026-10-09, моя рекомендация, принята).
- Кнопки строки сессии: «Очистить» — удалить собранные сообщения сессии (тексты и звук),
  сессия остаётся и собирает новые ответы; «Завершить» — то же, что `/tts-off` для этой
  сессии: сессия удаляется из списка, её тексты и файлы удаляются сразу, без подтверждения,
  её ответы больше не приходят (2026-10-09, моя рекомендация, принята).
- Хвост — на каждую сессию отдельно (размер из настроек плеера); список главного экрана
  показывает сообщения активной сессии; клик по сессии переключает и список, и плеер
  (2026-10-09, моя рекомендация, принята).
- `/tts-on` и `/tts-off` только включают и выключают запись текста для своей сессии
  (регистрация сессии в плеере); воспроизведение они не трогают (2026-10-09, сказано
  пользователем). Это отменяет нынешнее поведение: `tts-player-hook on/off` больше не зовёт
  `tts-player play/stop`, а моё постановление среза (10) «пока звучит свой текст, /tts-on
  ничего не делает, /tts-off ставит свой текст на паузу» снимается вместе с ним.
- Свой текст (экран «Свой текст») забирает на себя канал озвучки; сессии в это время
  продолжают записывать свой текст в память (2026-10-09, сказано пользователем).
- Клик по другой сессии: звук останавливается, выбранная сессия становится активной, её
  текущим становится первое непрослушанное сообщение, ждёт play/pause — как клик по строке
  (2026-10-09, моя рекомендация, принята).
- Сессия, в которой Claude Code закрыт без `/tts-off`, остаётся в списке, пока
  пользователь не нажмёт «Завершить» (2026-10-09, моя рекомендация, принята).
- `/tts-on` в сессии, которая уже в списке, ничего не меняет; плеер отвечает хуку «сессия уже
  в списке» (2026-10-09, моя рекомендация, принята).
- Первая сессия в пустом списке сразу становится активной — моё решение (пользователь не
  возразил).
- Завершена активная сессия → активной не становится никакая, пока пользователь не кликнет
  по сессии (2026-10-09, против моей рекомендации «следующая в списке»).
- Порядок: сначала спека кэша, затем сессии (моё предложение 2026-10-09, пользователь не
  возразил). Флаг `/tmp/claude-tts.on` и гейт по нему заменяются: задачи всех
  зарегистрированных сессий приходят в плеер по (11), в демон плеер отправляет только задачи
  активной (12).

Факты (проверено 2026-10-09 по коду):
- `~/.claude/hooks/tts-gate.sh` пропускает хуки озвучки (`speak-response.sh`,
  `speak-intermediate.sh`, `voice-context.sh`) только при `session_id` входа хука ==
  содержимому `/tmp/claude-tts.on`.
- «Сессия» `claude-tts` по умолчанию — закодированный путь проекта из `transcript_path`
  (`cli.py:1905–1911`); две сессии Claude Code одного проекта для него одна сессия.
  Переменная `CLAUDE_TTS_SESSION` подменяет её (`cli.py:1905`).
- Сообщение очереди хранит `session_id` (`audio.py:673`); пока демон его говорит,
  `~/.claude-tts/playback.json` → `current_message` содержит запись сообщения
  (`daemon.py:812`).
- Демон говорит очередь по одному сообщению, в порядке поступления.

## Цепочка

Согласована 2026-10-09. Строится на цепочке спеки кэша ((11)–(13)).

```
/tts-on  → tts-toggle.sh on  → tts-player-hook on → tts-player session add <UUID> <cwd>
/tts-off → tts-toggle.sh off → tts-player session remove <UUID>
                                        │ (14) команда сессии: файл в control/, плеер забирает
                                        ▼
TTS Player — список сессий; пишет sessions.json (кто в списке, кто активен)
                                        │ (15) sessions.json: читают гейт и CLI
                                        ▼
Stop-хук → tts-gate.sh: tts-player session has <UUID>?   (вместо флага /tmp/claude-tts.on)
             да → HOME=hook-home CLAUDE_TTS_SESSION=<UUID> claude-tts speak --from-hook
                    │ (11) задача хука с session_id = UUID
                    ▼
плеер: сообщение в хвост своей сессии;
       сессия активна и свой текст не звучит → (12) задача демону
       иначе — только текст, звук при проигрывании
```

## Контракты

Нумерация продолжает спеку кэша ((11)–(13)).

### (14) CLI → плеер: команда сессии

```
tts-player session add <uuid> <cwd> | remove <uuid> | has <uuid>
  add:    уже в списке → stdout «сессия уже в списке», exit 0; иначе запрос в
          $XDG_RUNTIME_DIR/tts-player/control/<ns>.json {"op":"add","session":…,"cwd":…}
          (сначала .tmp, затем rename)
  remove: запрос {"op":"remove","session":…}; нет в списке → «сессия не в списке», exit 0
  has:    exit 0 — в списке, 1 — нет (читает sessions.json, плеер не трогает)
  плеер не запущен → add/remove: exit 0 с сообщением; has → 1
плеер: забирает control/*.json монитором (как inbox/), выполняет, удаляет файл;
       не JSON / неизвестный op → файл удалён, строка в stderr
```

### (15) Плеер → гейт и CLI: список сессий

```
$XDG_RUNTIME_DIR/tts-player/sessions.json   пишет только плеер, атомарно
  {"active": "<uuid>" | null,
   "sessions": [{"id": "<uuid>", "project": "<последний компонент cwd>"}, …]}
```
