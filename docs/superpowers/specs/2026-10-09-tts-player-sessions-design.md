# TTS Player — несколько озвучиваемых сессий

**Статус:** в работе (обсуждение возобновлено 2026-10-09), карта не собрана. Реализуется после спеки кэша `2026-10-09-tts-player-text-cache-design.md` — опирается на её цепочку (11)–(13).

## Задача

Сейчас озвучивается одна сессия Claude Code — последняя, где вызван `/tts-on` (флаг
`/tmp/claude-tts.on`). Нужно: плеер ведёт список активных сессий; каждая собирает свои
озвученные сообщения; играет только выбранная сессия.

## Решения

Со слов пользователя, 2026-10-09:
- `/tts-on` передаёт текущую сессию плееру, плеер добавляет её в список активных сессий.
- Список сессий — на главном экране между рядом кнопок управления и списком воспроизведения.
- Строка сессии: ID; справа — кнопка завершения сессии (то же, что `/tts-off` из чата) и кнопка
  очистки.
- При завершении сессии все её файлы из её истории можно удалить.
- Клик по сессии делает её активной.
- Хук озвучки берёт ID сессии не из файла-флага, а спрашивает у плеера.
- Озвученные файлы попадают в список своей сессии.
- Проигрывается только активная сессия; остальные только собирают файлы в свой список.
- Синтезируется только активная сессия (2026-10-09, выбрано из: все / только активная /
  все, активная первой). Причина выбора — демон говорит очередь по одному сообщению, и
  ответ неактивной сессии задерживал бы речь активной.
- Неактивная сессия собирает текст ответов (задачи хука, контракт (11) спеки кэша); звук
  синтезируется, когда сессия стала активной и до сообщения дошло воспроизведение — тем же
  путём, что переозвучка устаревшего кэша (2026-10-09, моя рекомендация, принята).
- ID сессии — UUID сессии Claude Code; строка списка — «проект · первые 8 знаков UUID»
  (`TTSReader · 1dd2b064`), проект — последний компонент `cwd` сессии. Гейт передаёт хуку
  `CLAUDE_TTS_SESSION=<UUID>`; настройки `claude-tts` уровня сессии ведутся по UUID
  (2026-10-09, моя рекомендация, принята).
- Кнопки строки сессии: «Очистить» — удалить собранные сообщения сессии (тексты и звук),
  сессия остаётся и собирает новые ответы; «Завершить» — то же, что `/tts-off` для этой
  сессии: сессия удаляется из списка, её тексты и файлы удаляются сразу, без подтверждения,
  её ответы больше не приходят (2026-10-09, моя рекомендация, принята).
- Порядок: сначала спека кэша, затем сессии (моё предложение 2026-10-09, пользователь не
  возразил). Флаг `/tmp/claude-tts.on` и гейт по нему заменяются: задачи всех
  зарегистрированных сессий приходят в плеер по (11), в демон плеер отправляет только задачи
  активной (12).

Факты (проверено 2026-10-09 по коду):
- `~/.claude/hooks/tts-gate.sh` пропускает хуки озвучки (`speak-response.sh`,
  `speak-intermediate.sh`, `voice-context.sh`) только при `session_id` входа хука ==
  содержимому `/tmp/claude-tts.on`.
- «Сессия» `claude-tts` по умолчанию — закодированный путь проекта из `transcript_path`
  (`cli.py:1905–1911`); две сессии Claude Code одного проекта для него одна сессия.
  Переменная `CLAUDE_TTS_SESSION` подменяет её (`cli.py:1905`).
- Сообщение очереди хранит `session_id` (`audio.py:673`); пока демон его говорит,
  `~/.claude-tts/playback.json` → `current_message` содержит запись сообщения
  (`daemon.py:812`).
- Демон говорит очередь по одному сообщению, в порядке поступления.
