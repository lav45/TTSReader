# TTS Player — несколько озвучиваемых сессий

**Статус:** реализовано 2026-10-09 — пять срезов в master (планы `docs/superpowers/plans/2026-10-09-tts-player-sessions-*.md`), хуки вне репозитория переключены; ждёт проверки пользователем; 2026-10-11 число дорожек у заголовка папки убрано (сказано пользователем). Опирается на цепочку (11)–(13) спеки кэша `2026-10-09-tts-player-text-cache-design.md`.

## Задача

Сейчас озвучивается одна сессия Claude Code — последняя, где вызван `/tts-on` (флаг
`/tmp/claude-tts.on`). Нужно: плеер ведёт список активных сессий; каждая собирает свои
озвученные сообщения; играет только выбранная сессия.

## Решения

Со слов пользователя, 2026-10-09:
- `/tts-on` передаёт текущую сессию плееру, плеер добавляет её в список активных сессий.
- Список сессий — на главном экране между рядом кнопок управления и списком воспроизведения.
- Строка сессии: ID (кнопки управления — в ряду служебных кнопок наверху, см. ниже).
- При завершении сессии все её файлы из её истории можно удалить.
- Клик по сессии делает её активной.
- Хук озвучки берёт ID сессии не из файла-флага, а спрашивает у плеера.
- Озвученные файлы попадают в список своей сессии.
- Проигрывается только активная сессия; остальные только собирают файлы в свой список.
- Синтезируется только активная сессия (2026-10-09, выбрано из: все / только активная /
  все, активная первой). Причина выбора — демон говорит очередь по одному сообщению, и
  ответ неактивной сессии задерживал бы речь активной.
- Неактивная сессия собирает текст ответов (задачи хука, контракт (11) спеки кэша); звук
  синтезируется, когда сессия стала активной и до сообщения дошло воспроизведение — тем же
  путём, что переозвучка устаревшего кэша (2026-10-09, моя рекомендация, принята).
- ID сессии — UUID сессии Claude Code; строка списка — «проект · первые 8 знаков UUID»
  (`TTSReader · 1dd2b064`), проект — последний компонент `cwd` сессии. Гейт передаёт хуку
  `CLAUDE_TTS_SESSION=<UUID>`; настройки `claude-tts` уровня сессии ведутся по UUID
  (2026-10-09, моя рекомендация, принята).
- Кнопки строки сессии: «Очистить» — удалить собранные сообщения сессии (тексты и звук),
  сессия остаётся и собирает новые ответы; «Завершить» — то же, что `/tts-off` для этой
  сессии: сессия удаляется из списка, её тексты и файлы удаляются сразу, без подтверждения,
  её ответы больше не приходят (2026-10-09, моя рекомендация, принята).
- Хвост — на каждую сессию отдельно (размер из настроек плеера); список главного экрана
  показывает сообщения активной сессии; клик по сессии переключает и список, и плеер
  (2026-10-09, моя рекомендация, принята).
- `/tts-on` и `/tts-off` только включают и выключают запись текста для своей сессии
  (регистрация сессии в плеере); воспроизведение они не трогают (2026-10-09, сказано
  пользователем). Это отменяет нынешнее поведение: `tts-player-hook on/off` больше не зовёт
  `tts-player play/stop`, а моё постановление среза (10) «пока звучит свой текст, /tts-on
  ничего не делает, /tts-off ставит свой текст на паузу» снимается вместе с ним.
- Свой текст (экран «Свой текст») забирает на себя канал озвучки; сессии в это время
  продолжают записывать свой текст в память (2026-10-09, сказано пользователем).
- Клик по другой сессии: звук останавливается, выбранная сессия становится активной, её
  текущим становится первое непрослушанное сообщение, ждёт play/pause — как клик по строке
  (2026-10-09, моя рекомендация, принята).
- Сессия, в которой Claude Code закрыт без `/tts-off`, остаётся в списке, пока
  пользователь не нажмёт «Завершить» (2026-10-09, моя рекомендация, принята).
- `/tts-on` в сессии, которая уже в списке, ничего не меняет; плеер отвечает хуку «сессия уже
  в списке» (2026-10-09, моя рекомендация, принята).
- Первая сессия в пустом списке сразу становится активной — моё решение (пользователь не
  возразил).
- Завершена активная сессия → активной не становится никакая, пока пользователь не кликнет
  по сессии (2026-10-09, против моей рекомендации «следующая в списке»).
- Кнопки ряда служебных кнопок наверху управляют активной сессией; в строках сессий кнопок
  нет — только ID, клик делает сессию активной (2026-10-09, сказано пользователем; отменяет
  «справа в строке — кнопка завершения и кнопка очистки»). Мусорка — «Очистить» активной
  сессии; [stop] — «Завершить» активную сессию (то же, что `/tts-off` из её чата).
  Остановить звук — пауза плеера; прежний смысл [stop] («остановить звук») убран, кнопка
  остаётся как «Завершить» (подтверждено пользователем 2026-10-09).
- Порядок: сначала спека кэша, затем сессии (моё предложение 2026-10-09, пользователь не
  возразил). Флаг `/tmp/claude-tts.on` и гейт по нему заменяются: задачи всех
  зарегистрированных сессий приходят в плеер по (11), в демон плеер отправляет только задачи
  активной (12).

Факты (проверено 2026-10-09 по коду):
- `~/.claude/hooks/tts-gate.sh` пропускает хуки озвучки (`speak-response.sh`,
  `speak-intermediate.sh`, `voice-context.sh`) только при `session_id` входа хука ==
  содержимому `/tmp/claude-tts.on`.
- «Сессия» `claude-tts` по умолчанию — закодированный путь проекта из `transcript_path`
  (`cli.py:1905–1911`); две сессии Claude Code одного проекта для него одна сессия.
  Переменная `CLAUDE_TTS_SESSION` подменяет её (`cli.py:1905`).
- Сообщение очереди хранит `session_id` (`audio.py:673`); пока демон его говорит,
  `~/.claude-tts/playback.json` → `current_message` содержит запись сообщения
  (`daemon.py:812`).
- Демон говорит очередь по одному сообщению, в порядке поступления.

Решения при планировании (2026-10-09, мои; правки хуков вне репозитория и перезапуск плеера
при слиянии — с согласия пользователя):
- Срезы по порядку: (15) `sessions.json` и `session has`; (14) `session add/remove` через
  `control/`; переключение хуков (`tts-player-hook`, гейт, `tts-toggle.sh`, `tts-command.sh`);
  сессии внутри плеера (свой хвост, синтез только активной); окно (список сессий, кнопки).
  Гейт переключается раньше сессий внутри плеера: иначе плеер, принимающий задачи только
  зарегистрированных сессий, остался бы на живой установке без звука.
- `sessions.json` переживает выход плеера и читается при его старте: перезапуск плеера
  сессии не теряет. Пока плеер не запущен, `has` отвечает 1 по пробе блокировки, а не по файлу.
- `add`/`remove` при незапущенном плеере всё равно кладут запрос в `control/`: его заберёт
  старт плеера (`tts-player-hook on` запускает плеер отвязанно и не ждёт его). Сообщение в
  stdout говорит, что плеер не запущен и запрос выполнится при запуске.
- Ответ «сессия уже в списке» / «сессия не в списке» (и пропуск запроса) — только при пустой
  очереди `control/`: иначе запрос пишется всегда, а плеер выполняет `add`/`remove`
  идемпотентно. Сверка с одним `sessions.json` теряла запрос `/tts-off`, пришедший вслед за
  ещё не забранным `/tts-on` (финальное ревью среза (14)).
- Старт плеера удаляет из `control/` только `*.tmp` старше 60 с: свежий может писать CLI прямо
  сейчас (`tts-player-hook on` запускает плеер и сразу зовёт `session add`).
- `tts-player-hook on <uuid> <cwd>` — демон и плеер, как раньше, затем `tts-player session add`;
  `tts-player-hook off` убирается: `/tts-off` зовёт `tts-player session remove` прямо (по
  цепочке). Команды `tts-player stop`/`play` теряют последних потребителей и удаляются.
- Задача хука сессии не из списка удаляется со строкой в журнале (гонка `/tts-off` с уже
  запущенным хуком). Перед разбором задачи хука плеер забирает лежащие в `control/` запросы:
  `/tts-on` пишет `add` раньше, чем немедленная озвучка пишет задачу.
- Порядок задач демона общий для всех сессий: демон синтезирует их по одной, и предложение
  задачи сессии B завершает более раннее сообщение сессии A.
- Клик по строке уже активной сессии ничего не меняет (как клик по текущему сообщению).
- Известное ограничение (финальное ревью среза «сессии в плеере»): задачи прежней активной
  сессии, уже отданные демону до переключения, досинтезируются — отозвать задачу через (12)
  нельзя; отложенное сообщение новой активной встаёт в очередь демона после них. Их
  предложения попадают в сообщения своей сессии и не играют.

## Окно: сессии папками (реализовано 2026-10-10 в ветке `tts-player-session-folders`, ждёт проверки)

Со слов пользователя, 2026-10-09:
- Сессии и их звуковые дорожки показываются как папки с файлами — одним деревом вместо двух
  списков (сессий сверху и сообщений активной снизу).
- Сессия — папка: открыта — активна, закрыта — не активна.
- Дорожки (сообщения) — внутри открытой папки, с отступом от левого края.
- Клик по заголовку закрытой папки открывает её: сессия становится активной (как прежний клик по
  строке сессии), прежняя открытая закрывается. Клик по заголовку открытой папки закрывает её:
  активной сессии нет, звук стоп — плееру нужна команда «снять активность» (сейчас её снимает
  только «Завершить») (2026-10-09, моя рекомендация, принята).
- Заголовок папки: стрелка ▸/▾, значок закрытой/открытой папки, «проект · id», у правого края —
  число дорожек; открытая — жирным (2026-10-09, моя рекомендация; пользователь дополнил строку
  дорожки, я принял как согласие с остальным).
- Строка дорожки: первые слова текста, затем время прихода вторым столбцом, затем длительность;
  время и длительность прижаты к правому краю (2026-10-09, сказано пользователем; отменяет
  «HH:MM:SS  <первые слова>» в одной надписи).
- Знака «…» справа от длительности дорожки нет — ни у растущей, ни у отложенной (2026-10-09,
  сказано пользователем).
- Открытая папка заменяет выключатель автовоспроизведения: открыта — слушаю (ответы её сессии
  сразу уходят в синтез, после конца дорожки начинается следующая, новый ответ при тишине
  играет сам), закрыты все — ничего не звучит, сессии молча копят ответы в пределах `tail`.
  Выключатель и ключ `autoplay` в настройках плеера убираются (2026-10-09, предложено
  пользователем, моя схема принята).
- Открытие папки только открывает: фокуса нет (idle), ничего не играет; клик по дорожке выбирает
  её, ▶ играет — как сейчас (2026-10-09, выбрано из: только открыть / открыть и сразу играть;
  моя рекомендация, принята).
- Ни одна сессия не открывается сама: первая сессия в пустом списке больше не становится
  активной — иначе её ответы звучали бы без спроса (2026-10-09, следствие предыдущих, названо
  пользователю).
- «Прослушать одну дорожку и остановиться» без выключателя — пауза или закрытие папки.

- Кнопки «Завершить» в окне нет (2026-10-10, сказано пользователем): для живой сессии Claude Code
  это необратимо — `/tts-on` больше нет, вернуть её в список нечем, и она молчит до перезапуска. Сессию
  убирает только хук `SessionEnd`; корзина «Очистить» остаётся. Отменяет решение «Кнопки строки
  сессии: … «Завершить»» выше.

- Кнопок ⏮/⏭ в окне нет, команд плеера next/prev тоже (2026-10-10, сказано пользователем: не
  пользовался): другую дорожку выбирают щелчком по строке и ▶ (во время звука щелчок сразу
  играет выбранную, 2026-10-12 — спека настроек).

Меняет спеку `2026-10-09-tts-player-auto-sessions-design.md`: «включает автовоспроизведение» →
открывает папку; «выключение автовоспроизведения снимает фокус» → закрытие папки; пункт
«доиграло при выключенном автовоспроизведении» снимается — в открытой папке дорожки идут подряд;
«задача хука сразу в демон, если сессия активна и автовоспроизведение» → если сессия активна.

## Цепочка

Согласована 2026-10-09. Строится на цепочке спеки кэша ((11)–(13)).

```
/tts-on  → tts-toggle.sh on  → tts-player-hook on → tts-player session add <UUID> <cwd>
/tts-off → tts-toggle.sh off → tts-player session remove <UUID>
                                        │ (14) команда сессии: файл в control/, плеер забирает
                                        ▼
TTS Player — список сессий; пишет sessions.json (кто в списке, кто активен)
                                        │ (15) sessions.json: читают гейт и CLI
                                        ▼
Stop-хук → tts-gate.sh: tts-player session has <UUID>?   (вместо флага /tmp/claude-tts.on)
             да → HOME=hook-home CLAUDE_TTS_SESSION=<UUID> claude-tts speak --from-hook
                    │ (11) задача хука с session_id = UUID
                    ▼
плеер: сообщение в хвост своей сессии;
       сессия активна и свой текст не звучит → (12) задача демону
       иначе — только текст, звук при проигрывании
```

## Контракты

Нумерация продолжает спеку кэша ((11)–(13)).

### (14) CLI → плеер: команда сессии

```
tts-player session add <uuid> <cwd> | remove <uuid> | has <uuid>
  add:    уже в списке → stdout «сессия уже в списке», exit 0; иначе запрос в
          $XDG_RUNTIME_DIR/tts-player/control/<ns>.json {"op":"add","session":…,"cwd":…}
          (сначала .tmp, затем rename)
  remove: запрос {"op":"remove","session":…}; нет в списке → «сессия не в списке», exit 0
  has:    exit 0 — в списке, 1 — нет (читает sessions.json, плеер не трогает)
  плеер не запущен → add/remove: exit 0 с сообщением; has → 1
плеер: забирает control/*.json монитором (как inbox/), выполняет, удаляет файл;
       не JSON / неизвестный op → файл удалён, строка в stderr
```

### (15) Плеер → гейт и CLI: список сессий

```
$XDG_RUNTIME_DIR/tts-player/sessions.json   пишет только плеер, атомарно
  {"active": "<uuid>" | null,
   "sessions": [{"id": "<uuid>", "project": "<последний компонент cwd>"}, …]}
```
