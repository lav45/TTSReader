# TTS Player — кнопка автовоспроизведения

**Статус:** согласовано 2026-10-10, ждёт ревью спеки пользователем.

## Задача

Переслушиваю прошлую дорожку или останавливаюсь посреди неё — и новый ответ сессии не
начинает играть сам: на паузе автоперехода нет. Нужна кнопка, которая решает, что плеер
делает после конца дорожки: идёт дальше и ждёт новый ответ — или останавливается.

## Решения

- Одна кнопка-переключатель справа от ⏵/⏸ в ряду управления, два состояния — нажата /
  отжата, значок — двойная стрелка вправо (2026-10-10, сказано пользователем).
- Кнопка отвечает только за то, что происходит после конца дорожки (2026-10-10, сказано
  пользователем: «только за автовоспроизведение… больше ничего»):
  - нажата — играет следующая дорожка списка; следующей нет — плеер ждёт, и новый ответ
    играет сам, как сейчас в открытой папке;
  - отжата — доигравшая дорожка останавливает плеер; следующую, даже уже лежащую в списке,
    запускает пользователь (выбрано пользователем из: подряд до последней / стоп после каждой /
    подряд вместе с пришедшими; моя рекомендация была «подряд до последней», не принята).
  Отменяет записанное раньше в этой спеке «нажата: новый ответ играет сам, где бы ни стоял
  курсор»: курсор сам с дорожки не уходит.
- Нажата, дорожка стоит на паузе (повтор прослушанного или новая — неважно), пришёл новый
  ответ: плеер ничего не делает — пауза держит, ответ появляется в списке и уходит в синтез;
  его слушают щелчком по строке и ▶, а ▶ на паузе дослушивает текущую, и дальше по кнопке
  (2026-10-10, выбрано пользователем из: ничего, ждёт / курсор сам переходит на новый ответ и
  играет его; моя рекомендация).
- Нажата и звучит новый, ещё не прослушанный ответ: следующий новый встаёт в очередь и играет,
  когда текущий доиграет, — новое текущее не перебивает (2026-10-10, выбрано пользователем из:
  в очередь / всегда перебивать / перебивать только повтор; моя рекомендация).
- Отжата: новый ответ откладывается, как в закрытой папке, — в синтез демона он уходит по ▶;
  первый ▶ ждёт синтеза первого предложения (2026-10-10, выбрано пользователем из: сразу в
  синтез / отложить до ▶; сначала выбрано «сразу», затем пересмотрено пользователем; моя
  рекомендация была «сразу»).
- Отжата: история режется до `tail`, как у закрытой папки, — лишние, самые старые, удаляются
  с файлами, в том числе непрослушанные (2026-10-10, выбрано пользователем из: копится, пока
  папка открыта / режется до `tail`; моя рекомендация была «копится»). Вместе с предыдущим:
  отжатая кнопка делает открытую папку по синтезу и истории такой же, как закрытая; отличие —
  её дорожки видны и играют по щелчку. Дорожка под курсором (на паузе, выбранная) места в
  `tail` не занимает и не удаляется — действующее правило `MessageQueue.trim` (следствие,
  названо пользователю).
- Нажатие кнопки только включает режим: звук не начинается, накопленные за время отжатой
  кнопки ответы остаются отложенными; новый ответ заиграет сам, если плеер ждёт (2026-10-10,
  выбрано пользователем из: только режим / сразу к самому новому / сразу подряд с первого
  накопленного; моя рекомендация).
- Положение кнопки одно на плеер: переключение сессии его не меняет. Хранится в
  `settings.json` плеера под ключом `autoplay` (true — нажата) и переживает перезапуск; нет
  ключа — нажата, как плеер ведёт себя сейчас (2026-10-10, выбрано пользователем из: одна на
  плеер / своя у каждой сессии; моя рекомендация; имя ключа — моё: прежний выключатель жил под
  ним же, в текущем файле пользователя его нет).
- Клик по кнопке, а `settings.json` не записался: режим всё равно переключается до выхода из
  плеера, кнопка остаётся в новом положении, ошибка — строкой в `player.log`; после
  перезапуска действует записанное в файле (2026-10-10, выбрано пользователем из: режим
  переключается / кнопка возвращается / строка ошибки на главном экране; моя рекомендация).
- «Сохранить» на экране настроек пишет `autoplay` таким, какой он сейчас, — хвост и
  приглушение его не сбрасывают (моё следствие из «пишутся все ключи», названо пользователю).
- Нажатая кнопка не отменяет свой текст и `tts-player stop` (`/tts-off`): пока звучит свой
  текст, плеер сам ничего не начинает; после `stop` стоит до ▶ — действующие правила (моё
  решение, названо пользователю).
- Отжатие кнопки, пока звучит дорожка: она доигрывает до конца, и плеер стоит; следующая не
  начинается. Ответы, отданные демону при нажатой кнопке, остаются в синтезе и играют по
  щелчку без задержки; пришедшие после отжатия откладываются до ▶ (2026-10-10, выбрано
  пользователем из: доигрывает и стоп / обрывается сразу; моя рекомендация).
- Вид: переключатель GTK со значком `media-seek-forward-symbolic` (системная двойная стрелка
  вправо, тот же набор, что у шестерёнки и корзины); нажатую тема рисует вдавленной. Подсказка
  постоянная — «Автовоспроизведение: следующая дорожка и новые ответы» (2026-10-10, значок и вид
  — моё предложение, принято; подсказка выбрана пользователем из: постоянная / меняется с
  состоянием).
- Отметки ожидания в истории нет: что плеер ждёт новый ответ, показывает нажатая кнопка
  (2026-10-10, сказано пользователем; отменяет обсуждавшуюся строку-заглушку в конце списка).
- Меняет решение спеки `2026-10-09-tts-player-sessions-design.md` «Открытая папка заменяет
  выключатель автовоспроизведения»: выключатель возвращается кнопкой в ряду управления;
  открытая папка без нажатой кнопки ведёт себя по синтезу и истории как закрытая
  (2026-10-10, названо пользователю).

## Цепочка

```
кнопка ⏩ (окно) --toggled--> Player.set_autoplay(bool) --> PlayerSettings.save (6)
                                       |
                                       +--> конец дорожки: следующая / ожидание / стоп
                                       +--> задача хука открытой сессии: в демон (12) / отложена
                                       +--> обрезка до tail (MessageQueue.trim)
старт плеера: PlayerSettings.load (6) --> Player.apply_prefs --> кнопка показывает autoplay
```

## Контракты

### (6) Плеер ↔ его файл настроек — ключ `autoplay` возвращается

Меняет (6) спеки `2026-10-09-tts-player-settings-design.md`: пишущая сторона `autoplay` —
кнопка ⏩ в ряду управления; поведение при `false` — ниже, вместо прежнего.

```
~/.config/tts-player/settings.json      ($XDG_CONFIG_HOME, если задан)
  {"tail": <целое 1–20>, "duck": <целое 0–100>, "autoplay": <true|false>}

нет файла / нет ключа autoplay       → autoplay = true
autoplay не bool                     → autoplay = true, строка в player.log; остальные как есть
сохранение                           → как сейчас: атомарно, пишутся все ключи
сбой записи по клику кнопки          → строка в player.log; плеер работает с новым значением
                                       до выхода
autoplay = true                      → как сейчас в открытой папке: конец дорожки — следующая
                                       по порядку; следующей нет — ожидание, новый ответ играет
                                       сам; новый при звучащем — в очередь; задача хука открытой
                                       сессии сразу в демон (12); история с фокусом
autoplay = false                     → конец дорожки — статус stopped, следующая не начинается;
                                       новый ответ открытой сессии отложен (deferred), в демон по ▶;
                                       история режется до tail, как у закрытой папки; дорожка
                                       под курсором места в tail не занимает
переключение true → false            → звучащая доигрывает, затем stopped; отданные демону
                                       задачи остаются в синтезе
переключение false → true            → звук не начинается; отложенные остаются отложенными
не отменяет                          → свой текст (hold): плеер сам ничего не начинает;
                                       tts-player stop: стоит до ▶; пауза: новый ответ ждёт
```
