# TTS Player — сессии без `/tts-on`

**Статус:** дизайн согласован 2026-10-09, на ревью пользователя. Меняет решения спеки сессий
`2026-10-09-tts-player-sessions-design.md` (сессию добавляет `/tts-on`, убирает `/tts-off`).

## Задача

Сейчас сессия попадает в плеер командой `/tts-on` и уходит из него по `/tts-off`; на
`/tts-on` сразу звучит последний ответ. Нужно: каждая новая сессия Claude Code сама попадает
в плеер и молча копит сообщения в пределах длины истории; слушать пользователь начинает сам из
плеера.

## Решения

Выключатель автовоспроизведения заменён открытой папкой сессии (2026-10-09) — пункты ниже про
автовоспроизведение читаются по разделу «Окно: сессии папками» спеки сессий.

Со слов пользователя, 2026-10-09:
- `/tts-on` и `/tts-off` убираются.
- Новая сессия Claude Code при запуске сразу добавляется в плеер; ничего не проигрывается.
- Сообщения сессии накапливаются; сверх максимальной длины истории («Хвост очереди», `tail`)
  удаляются, самые старые первыми.
- Слушать пользователь начинает сам: заходит в плеер, проигрывает нужный ответ и включает
  автовоспроизведение (выключатель уже есть в ряду кнопок главного экрана).
- Выключение автовоспроизведения снимает фокус с проигранной дорожки (текущего сообщения нет), и
  сообщения снова удаляются сверх длины истории — как у новой сессии.
- Пока сообщение на паузе, поступающие сообщения копятся без ограничения длины.
- Длина истории держится на фокусе — есть ли текущее сообщение. Нет фокуса — очередь сессии
  целиком (прослушанные и нет) режется до `tail` сразу, самые старые первыми, и так с каждым
  новым сообщением. Фокус есть (играет, пауза) — сообщения копятся; позади курсора начатые
  ограничены `tail`, как сейчас (моя формулировка строк пользователя, принята вместе со следующим
  пунктом).
- Сообщение доиграло при выключенном автовоспроизведении — фокус снимается, очередь режется до
  `tail` («послушал и отпустил»; выбрано из: снять фокус / курсор на следующее, stopped, как
  сейчас; причина — иначе при выключенном автовоспроизведении фокус не снимается никогда и
  очередь растёт без предела; моя рекомендация, принята).
- Клик по сессии только делает её активной и показывает её список: фокуса нет (idle), её очередь
  режется до `tail`. Фокус появляется только от воспроизведения — клик по строке или ▶ (выбрано
  из: без фокуса / курсор на первое непрослушанное, stopped, как сейчас; моя рекомендация,
  принята).
- Задача хука сразу уходит в демон, только если её сессия активна и автовоспроизведение включено;
  иначе сообщение отложено (только текст) и синтезируется, когда до него дошло воспроизведение
  (клик по строке, «назад», автопереход), и играет по мере прихода предложений (выбрано из:
  синтез по слушанию / активная сессия синтезируется всегда; причина — демон работает, только
  когда пользователь слушает; цена — звук после клика через несколько секунд; моя рекомендация,
  принята).
- Активной становится только первая сессия в пустом списке, как сейчас; остальные выбираются
  кликом (выбрано из: как сейчас / каждая новая активна; причина — запуск сессии не перебивает
  звук и не переключает список; моя рекомендация, принята).
- Хук Claude Code `SessionEnd` (выход, `/clear`) убирает сессию из плеера, любую, в том числе
  активную: как «Завершить» — звук стоп, тексты и файлы сессии удалены. Кнопка «Завершить»
  остаётся (выбрано пользователем из: SessionEnd убирает любую / кроме активной / только кнопка;
  я рекомендовал «кроме активной» — `/clear` посреди прослушивания обрывает звук и удаляет хвост).
- Повторный `SessionStart` той же сессии (`--resume`) ничего не меняет: сессия уже в списке.
- Хук `SessionStart` зовёт `tts-player-hook start` (JSON хука на stdin) — то, что звал `/tts-on`: демон с
  обёрткой, плеер в трее, `session add`. Гейт `tts-gate.sh` остаётся как есть (выбрано из:
  SessionStart поднимает всё / автозапуск с рабочим столом и только `session add`; причина — один
  механизм запуска, и упавший плеер поднимает следующая сессия; моя рекомендация, принята).
- `start` в режиме claude-tts не `queue` ничего не запускает и сессию не добавляет — как прежний
  `tts-toggle.sh` (решение при исполнении); `end` гейта не имеет.
- Путь к хуку в `settings.json` — симлинк `~/.local/bin/tts-player-hook`, как в установке из README.
- Сессии, запущенные до перехода, в список не попадают и молчат до перезапуска; это шаг в README
  перехода (моё решение: случай разовый).

Отменено (вариант до 2026-10-09, «хвост переписки при `/tts-on`»): чтение N последних сообщений
из транскрипта при `/tts-on` — команды больше нет.

## Цепочка взаимодействия

```
Claude Code SessionStart ─► tts-player-hook start  (stdin: JSON хука)
                              ├─ claude-tts daemon start|restart (daemon-bin первым в PATH)
                              ├─ tts-player --tray
                              └─ tts-player session add <uuid> <cwd> ─► control/ ─► Player.add_session
Claude Code SessionEnd ───► tts-player-hook end    (stdin: JSON хука)
                              └─ tts-player session remove <uuid> ─► control/ ─► Player.remove_session
Stop / PostToolUse ─► tts-gate.sh ─► claude-tts speak ─► hook-home/queue ─► Player._on_hook_task
                                    (сессия активна и автовоспроизведение → демон, иначе отложено)
```

Удаляются (вне репозитория): `~/.claude/hooks/tts-command.sh` и его строка UserPromptSubmit,
`tts-toggle.sh`, `~/.claude/commands/tts-on.md`, `tts-off.md`. Стык `session add|remove` →
`control/` — контракт (14) спеки сессий, не меняется.

## Контракты

### `tts-player-hook start|end` ← хуки SessionStart и SessionEnd Claude Code

```
tts-player-hook start     # хук SessionStart
  stdin:  {"session_id": "<uuid>", "cwd": "<path>", "source": "startup|resume|clear|compact", …}
  делает: демон (нет — claude-tts daemon start; жив без daemon-bin первым в PATH — restart через
          setsid), плеер (не запущен — tts-player --tray через setsid), затем
          tts-player session add <session_id> <cwd>          # как прежний `on`, ничего не ждёт
tts-player-hook end       # хук SessionEnd
  stdin:  {"session_id": "<uuid>", "reason": "clear|logout|prompt_input_exit|other", …}
  делает: tts-player session remove <session_id>     # плеер не запущен — уберётся при его запуске
stdout:   пусто
журнал:   $XDG_RUNTIME_DIR/tts-player/hook.log — строки состояния (демон, плеер, вывод session
          add|remove, предупреждение о перезапуске демона), дописываются
код:      0; 1 + строка в stderr — stdin не JSON-объект, нет session_id (у start и cwd) строкой,
          нет claude-tts (start) или tts-player в PATH, нет XDG_RUNTIME_DIR,
          session add|remove не записал запрос
          иные аргументы — usage в stderr, код 1, ничего не запускается и stdin не читается
тесты:    TTS_HOOK_PROC, TTS_HOOK_HOME — как сейчас

~/.claude/settings.json:
  "SessionStart": [{"hooks": [{"type": "command",
                    "command": "/home/lav45/.local/bin/tts-player-hook start", "timeout": 5}]}]
  "SessionEnd":   [{"hooks": [{"type": "command",
                    "command": "/home/lav45/.local/bin/tts-player-hook end", "timeout": 5}]}]
```

## Открытые вопросы

- Свой текст (удержание, hold) без фокуса: режется ли очередь до `tail`, пока звучит свой текст, —
  по правилу «нет фокуса» да; важно, если свой текст долгий, а ответы сессии идут потоком.
