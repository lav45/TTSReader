# TTS Player — экран настроек

**Статус:** реализовано 2026-10-09 — контракты (5)–(10) в master; ждёт ручной проверки пользователем.

## Задача

В окне плеера: маленькая кнопка очистки буфера с иконкой мусорки у левого края, рядом —
маленькая кнопка-шестерёнка. Шестерёнка открывает в том же окне экран настроек: скорость
воспроизведения, список доступных голосов, кнопка «Сохранить», стрелка назад на главный экран.

## Решения

Согласовано (со слов пользователя, 2026-10-09):
- Кнопка «Очистить буфер» — маленькая, иконка мусорки, прижата к левому краю.
- Рядом с ней — маленькая кнопка-шестерёнка; экран настроек открывается в том же окне.
- На экране настроек: скорость воспроизведения, список доступных голосов, кнопка «Сохранить».
- Стрелка назад возвращает на главный экран.
- «Скорость воспроизведения» — скорость синтеза в `claude-tts` (поле `speed` персоны), а не
  темп плеера. Действует со следующего синтезированного предложения; буфер доигрывает в
  прежнем темпе. «Сохранить» пишет голос и скорость в настройки `claude-tts`.
- На экране настроек — сколько последних сообщений держит плеер (хвост, сейчас 5 — константа
  в `tts_player/queue.py`). Это настройка плеера, не `claude-tts`.
- «Сохранить» применяет голос и скорость ко всем проектам: плеер пишет в
  `~/.claude-tts/config.json` поле `active_persona` и `speed` выбранной персоны (команды CLI
  для глобальной персоны нет). Выбрано пользователем вместо «к озвучиваемому проекту» (моя
  рекомендация). Цена: прямая запись в чужой файл — формат `claude-tts` становится контрактом
  плеера; запись должна быть атомарной, как у `claude-tts` (`atomic_write_json`).
- «Сохранить» сбрасывает переопределения проектов: удаляет `persona` и `speed` из всех
  `~/.claude-tts/sessions.d/*.json` и очищает `project_personas` — «ко всем» буквально.
  Выбрано пользователем вместо «не трогать и показывать» (моя рекомендация). Цена: теряются
  `/tts-speed` и `/tts-persona`, заданные в сессиях (сейчас — `"speed": 1.6` у mock-server).
- Скорость одна на все голоса: «Сохранить» пишет одно значение `speed` во все персоны
  (как `claude-tts speed --default --all`); смена голоса темп не меняет. Выбрано
  пользователем вместо «у каждого голоса своя» (моя рекомендация). Цена: собственные
  скорости персон теряются (`claude-prime` 2.0, `ru-denis` 1.0). Поле при открытии экрана
  показывает `speed` активной персоны — моё решение.
- Уменьшение хвоста — постепенно: лишние начатые сообщения уходят по одному, по мере начала
  новых. Выбрано пользователем вместо «удалить сразу» (моя рекомендация). Цена: какое-то
  время в списке больше сообщений, чем задано. Допустимо 1–20; хранится в
  `~/.config/tts-player/settings.json` — моё решение, пользователь мог поправить и не стал.
- Кнопка [stop] в окне выполняет хук, который вызывает `/tts-off` (добавлено 2026-10-09,
  в ходе исполнения среза (5)): `~/.claude/hooks/tts-toggle.sh off`. Хуку нужен
  `CLAUDE_CODE_SESSION_ID`; у плеера сессии нет — ID берётся из `/tmp/claude-tts.on`
  (озвучиваемая сессия). Хук снимает флаг и зовёт `tts-player-hook off`.
- Кнопка [stop] — маленькая иконка `system-shutdown-symbolic` внизу слева рядом с мусоркой
  и шестерёнкой, подсказка «Выключить озвучку (/tts-off)»; неактивна, когда флага нет.
- Клик мышью по строке списка сообщений делает это сообщение текущим (сообщено
  пользователем 2026-10-09 как дефект: сейчас до сообщения доходят только через [prev]).
  Список был сделан только для показа (`SelectionMode.NONE`, `tts_player/window.py`) —
  клик по строке в спеке плеера не обсуждался. Решено пользователем: одиночный клик выбирает
  сообщение — звук останавливается, выбранное становится текущим на позиции 0 и ждёт
  play/pause; клик по текущему ничего не делает (сначала было «сразу играет», пересмотрено
  2026-10-09).
- Кнопки управления (сказано пользователем 2026-10-09): кнопка stop из ряда управления
  убирается, pause и play объединяются в одну — ряд `[prev] [play/pause] [next]`. Кнопка:
  играет → пауза; пауза → продолжить с места; стоп или конец без текущего звука → играть с
  позиции курсора (как прежний play). Состояние «стоп» остаётся у плеера для команды
  `tts-player stop` (`/tts-off`) — моё решение: контракт (4) от кнопок окна не зависит.
- Кнопка-переключатель автовоспроизведения — справа в ряду служебных кнопок (сказано «внизу
  справа», когда ряд был внизу; ряд переехал наверх — моё решение), иконку выбираю я:
  `media-playlist-consecutive-symbolic`. Сейчас автопереход к следующему сообщению всегда
  включён (решение спеки плеера «сам переходит к следующему»). Выключатель отвечает только
  за проигрывание файлов из буфера (сказано пользователем 2026-10-09): выключен — плеер сам
  не начинает ни следующее сообщение после конца текущего, ни новое, пришедшее в тишине;
  играет только по команде (play/pause, клик по строке, prev/next). Озвучку целиком
  включает и выключает не он, а `/tts-on` и кнопка [stop]. Состояние хранится между
  запусками в файле настроек плеера (контракт (6)) — моё решение.
- Порядок главного экрана сверху вниз (сказано пользователем 2026-10-09): ряд служебных
  кнопок (слева мусорка, шестерёнка, [stop]; справа выключатель автовоспроизведения) →
  история воспроизведения (список сообщений) → плеер (ползунок, `[prev] [play/pause] [next]`,
  время). Заголовок текущего сообщения убирается: он дублирует выделенную строку истории
  (сказано пользователем 2026-10-09).
- Приглушение остальных звуков, пока плеер говорит (сказано пользователем 2026-10-09,
  способ «плеер сам приглушает остальные потоки» — моя рекомендация, принята): плеер через
  `pactl` уменьшает громкость всех чужих потоков до N % от их текущей и возвращает
  запомненную. N — на экране настроек. Встроенное приглушение WirePlumber по ролям отклонено:
  выключено в системе, включение меняет маршрутизацию всех приложений, браузер и Telegram роль
  «music» не ставят.
- Экран «озвучить свой текст» (сказано пользователем 2026-10-09): ещё одна кнопка в ряду
  служебных кнопок открывает в том же окне экран с полем ввода текста (textarea), снизу —
  плеер: ползунок и кнопка [play|pause]. Озвученная дорожка принадлежит только этому экрану и
  в списке главного экрана не появляется. Изменённый текст озвучивается заново.
- Синтез своего текста — внутренней функцией пакета `daemon_generate_speech` отдельным
  процессом в окружении `claude-tts` (моя рекомендация, принята 2026-10-09). Цена: функция не
  публичная, обновление `claude-tts` может её сломать — тогда экран показывает «синтез
  недоступен», остальной плеер работает.
- Play на экране своего текста ставит главный плеер на паузу; пока играет свой текст, главный
  плеер сам ничего не начинает (автовоспроизведение тоже ждёт); после конца или паузы своего
  текста главный остаётся на паузе до команды пользователя (моя рекомендация, принята
  2026-10-09). Голос — активная персона `claude-tts` (моё решение).
- Длинный свой текст синтезируется по предложениям: звук начинается с первого, следующие
  синтезируются, пока играет предыдущее; ползунок растёт по мере синтеза (решено пользователем
  2026-10-09).
- «Сохранить» оставляет экран настроек открытым (сказано пользователем 2026-10-09; было
  моё постановление «успех — на главный экран», отменено). Внизу экрана узкий блок с
  результатом: «Настройки сохранены» на зелёном фоне или текст ошибки на красном. Ошибка
  загрузки настроек `claude-tts` при открытии экрана показывается в том же блоке на красном;
  при каждом открытии экрана блок очищается — моё решение.
- Плеер остаётся на перехвате звука демона (решено пользователем 2026-10-09, «пока»).
  Проверенная альтернатива «плеер сам читает очередь и синтезирует» отложена: хук
  `claude-tts` в режиме queue пишет в очередь только при живом демоне (`audio.py:731`,
  `daemon_healthy()` — свежий `daemon.heartbeat` ≤ 30 с или живой PID), без демона речь молча
  пропускается. Обходы — подделка heartbeat или свой Stop-хук с повтором логики
  `speak --from-hook`. Задержка синтеза при этом приемлема: 1,4 с первое предложение с
  загрузкой модели, 0,55 с следующее на прогретой (проверено 2026-10-09).
- Нижний ряд плеера: время слева, кнопки `[prev] [play/pause] [next]` справа (сказано
  пользователем 2026-10-09; было наоборот).
- Ряд служебных кнопок наверху: шестерёнка — первая слева, затем мусорка и [stop]
  (сказано пользователем 2026-10-09).

Факты о `claude-tts` 9.20.1 (проверено 2026-10-09 по `config.json` и `--help`):
- голоса — персоны в `~/.claude-tts/config.json` (`personas`), глобальная — `active_persona`;
  поле `voice` (Piper) или `voice_sherpa` + `speaker_sherpa` (sherpa-onnx);
- скорость — поле `speed` персоны (0.5–4.0), смена для персоны: `claude-tts speed --default <v>`;
- персона и скорость переопределяются на уровне проекта и сессии (`sessions.d/*.json`);
  у плеера сессии нет;
- «сессия» `claude-tts` — не UUID Claude Code, а закодированный путь проекта
  (`latest.session` = `-home-lav45-Programs-TTSReader`, файлы `sessions.d/<путь>.json`);
  флаг `/tmp/claude-tts.on` хранит UUID сессии Claude Code;
- команды для глобальной персоны нет: `claude-tts persona <имя>` пишет персону сессии,
  `--project` — проекта; `active_persona` меняет только установщик. Без `CLAUDE_TTS_SESSION`
  команда, вызванная из плеера, попадёт в сессию из `active/latest.session` — последнюю
  закреплённую, не обязательно озвучиваемую;
- `claude-tts speed --default <v>` пишет `speed` в персону, которую видит сессия вызова.
- Команды «синтезировать текст в файл» у CLI нет: `speak` и HTTP-мост ставят текст в очередь
  демона, а звук демона идёт через обёртку `paplay` в буфер главного экрана. Внутренняя функция
  `claude_code_tts.daemon.daemon_generate_speech(text, persona, output_file) -> bool` пишет WAV
  с настройками персоны; вызвана из Python-окружения пакета
  (`~/.local/share/uv/tools/claude-code-tts/bin/python`) отдельным процессом — работает:
  два предложения, `supertonic-3`, 1,85 с вместе с загрузкой модели, 2,35 с звука (проверено
  2026-10-09). Это не публичный интерфейс пакета: обновление `claude-tts` может её изменить.

## Контракты

Нумерация продолжает спеку плеера `2026-10-09-tts-player-design.md` (контракты (1)–(4)).

### (5) Плеер ↔ настройки `claude-tts`

Пишущая и читающая сторона — плеер; второй читатель — демон `claude-tts` 9.20.1 (не
меняется). Формат — подмножество `~/.claude-tts/config.json`, которое плеер читает и пишет;
остальные ключи сохраняются как есть.

```
~/.claude-tts/config.json
  {
    "active_persona": "<имя>",                       читается, пишется
    "personas": {                                    читается
      "<имя>": {"description": "<строка>",           читается (подпись в списке)
                "speed": <число 0.5–4.0>, ...}       пишется во все персоны
    },
    "project_personas": {...},                       удаляется при сохранении
    ...                                              не трогается
  }
~/.claude-tts/sessions.d/<сессия>.json
  {"persona": "<имя>", "speed": <число>, ...}        persona, speed удаляются; остальное как есть

чтение (открытие экрана настроек):
  голоса   = ключи personas, подпись — description
  выбран   = active_persona
  скорость = personas[active_persona].speed
  нет файла / не JSON / нет personas
           → голос и скорость неактивны, строка с причиной на экране; хвост доступен
сохранение («Сохранить»):
  config.json перечитывается в момент сохранения (не данные, прочитанные при открытии)
  active_persona ← выбранный голос
  personas[*].speed ← скорость
  project_personas удаляется
  sessions.d/*.json: удалить ключи persona и speed
  каждый файл — атомарно: временный файл в том же каталоге + rename
  успех → экран остаётся, блок результата «Настройки сохранены» на зелёном
  ошибка чтения или записи → экран остаётся, текст ошибки в блоке результата на красном;
                             уже записанные файлы не откатываются
```

### (7) Плеер → хук `/tts-off`

Пишущая сторона — кнопка [stop] окна; читающая — `~/.claude/hooks/tts-toggle.sh` (не меняется).

```
флаг   /tmp/claude-tts.on — UUID озвучиваемой сессии Claude Code (пишет tts-toggle.sh on)
кнопка активна ⇔ флаг существует и непуст (проверка при обновлении окна)
клик   → CLAUDE_CODE_SESSION_ID=<содержимое флага> ~/.claude/hooks/tts-toggle.sh off
         процесс отвязан от главного цикла GTK, stdout и stderr → stderr плеера (player.log)
хук    флаг == сессия → rm флаг; «Озвучка выключена…»; tts-player-hook off → tts-player stop
         → SIGUSR1 этому же плееру → stop_playback()
нет хука / не запустился / exit ≠ 0 → строка в stderr плеера; окно не меняется
```

### (8) Окно → плеер: выбор сообщения кликом

Пишущая сторона — список сообщений окна; читающая — `Player`. Пересмотрено пользователем
2026-10-09: клик только выбирает, играет кнопка play/pause.

```
окно   строка списка активируется одиночным кликом → player.play_message(<Message строки>)
       строка i соответствует state.messages[i]
Player.play_message(message: Message) -> None      # «выбрать»
  message нет в очереди (вытеснено / очищено к моменту клика) → ничего не меняется
  message == текущее (начатое или нет, в любом статусе) → ничего не меняется
  иначе: звук стоп (повтор при отказе вывода снят); покидаемое текущее → прослушано, только
         если начато и синтезировано целиком; message → текущее, позиция 0, статус stopped,
         не начато (в хвост войдёт при первом play/pause)
`tts-player play` (`/tts-on`) = play/pause из stopped / idle, в том числе при выключенном
автовоспроизведении — моё решение: команда возобновляет озвучку явно
```

### (9) Плеер → звуковой сервер: приглушение чужих потоков

Пишущая сторона — плеер; читающая — PipeWire через `pactl` (pipewire-pulse; проверено
2026-10-09: PipeWire 1.0.5, `pactl info` отвечает).

```
настройка  "duck": <целое 0–100> в settings.json плеера (контракт (6)); по умолчанию 30;
           100 — не приглушать; экран настроек — поле «Приглушать другие звуки до, %»
начало     статус плеера стал playing (в том числе ожидание следующего предложения
           растущего сообщения — моё решение: без «дрожания» громкости между предложениями)
             → pactl list sink-inputs: каждый поток, кроме потоков самого плеера
               (application.process.id == PID плеера), — запомнить громкость каналов,
               pactl set-sink-input-volume <id> <громкость × N/100>
           поток, появившийся во время речи, тоже приглушается
конец      статус paused / stopped / idle или выход плеера
             → каждому запомненному потоку, который ещё существует, вернуть запомненную громкость
след       запомненные громкости — в $XDG_RUNTIME_DIR/tts-player/duck.json на время приглушения;
           при старте плеера файл есть → вернуть громкости и удалить файл (остаток после падения)
           для каждого потока помнятся индекс, application.name и application.process.id;
           громкость возвращается только потоку с тем же индексом и теми же свойствами
           (индекс мог достаться новому потоку) — моё решение после ревью
возраст   приглушаются только потоки, живущие ≥ 5 с (решено пользователем 2026-10-09 вместо
           «исправлять задним числом»): короткие звуки (уведомления) не трогаются, и
           WirePlumber restore-stream не запоминает им сниженную громкость. Потоки, уже
           звучащие в момент начала речи, считаются давними (их возраст неизвестен) — моё
           решение; цена: короткий звук, начавшийся за мгновение до речи и закончившийся во
           время неё, оставит приложению сниженную громкость. Новые потоки во время речи
           приглушаются, когда им исполнится 5 с.
сироты    приглушённый поток, закончившийся во время речи (WirePlumber restore-stream
           запоминает приложению сниженную громкость) → по application.name запомнить
           исходную и сниженную громкость в $XDG_RUNTIME_DIR/tts-player/duck-orphans.json
           (решено пользователем 2026-10-09 вдобавок к правилу 5 с)
           новый поток того же приложения:
             во время речи → приглушается сразу от исходной громкости сироты; сирота снята
             вне речи, громкость == сниженной (±1) → вернуть исходную; сирота снята
             вне речи, громкость другая (пользователь поправил сам) → сирота снята, поток не трогать
           «новый» — поток, которого не было до начала речи (появился во время неё или после):
           его громкость выдал restore-stream, а не пользователь; звучавшие до речи (соседние
           вкладки) не трогаются; и в речи, и вне её — только при громкости == сниженной ±1;
           пара (исходная, сниженная) приложения действует и пока его приглушённый поток жив:
           новая вкладка во время речи получает исходную, а не сниженную как исходную;
           сирота применяется ко всем подходящим новым потокам одного прохода
           (уточнено после двух ревью — моё решение)
           опрос вне речи — 10 минут после последнего изменения сирот, дальше — при начале речи
           recover() после падения сирот не создаёт (след не хранит процент) — цена
           пока сироты есть, плеер проверяет список потоков раз в 2 с и вне речи; файл сирот
           переживает перезапуск плеера, но не выход из сеанса — моё решение
ошибка     нет pactl / код ≠ 0 → строка в stderr плеера; воспроизведение не прерывается
```

### (10) Плеер ↔ процесс синтеза своего текста

Пишущая сторона — `TextSpeaker` в процессе плеера (экран «Свой текст»); читающая — процесс
синтеза в Python-окружении `claude-tts`. Согласовано 2026-10-09.

### (6) Плеер ↔ его файл настроек

Пишущая сторона — окно (экран настроек — хвост; выключатель справа в ряду служебных кнопок — автовоспроизведение);
читающая — плеер при старте и сразу после записи.

```
~/.config/tts-player/settings.json      ($XDG_CONFIG_HOME, если задан)
  {"tail": <целое 1–20>, "autoplay": <true|false>, "duck": <целое 0–100>}

нет файла                              → tail = 5, autoplay = true, duck = 30
не JSON / не объект                    → все по умолчанию, строка в stderr (player.log)
tail вне 1–20 / не целое (bool — не целое) → tail = 5, строка в stderr; autoplay читается как есть
autoplay не bool                       → autoplay = true, строка в stderr; tail читается как есть
duck вне 0–100 / не целое               → duck = 30, строка в stderr; остальные читаются как есть
сохранение                             → атомарно: временный файл в том же каталоге + rename;
                                         каталог создаётся; пишутся все ключи
новый tail меньше прежнего             → лишние начатые сообщения уходят по одному при начале новых
новый tail больше прежнего             → новые сообщения перестают вытеснять старые до нового предела
autoplay = false                       → плеер сам не начинает ни следующее сообщение после конца
                                         текущего, ни новое, пришедшее в тишине; конец сообщения →
                                         текущее отмечено прослушанным, статус stopped; текущим
                                         становится следующее по порядку сообщение с позиции 0,
                                         если оно есть (моё решение: play/pause продолжает
                                         слушать по порядку); новое сообщение в тишине только
                                         появляется в списке; play/pause без текущего начинает
                                         первое непрослушанное; play/pause на доигранном
                                         текущем (позиция в конце), после которого уже есть
                                         следующее, начинает следующее с 0 — моё решение
```
