# TTS Player — плеер озвучки Claude Code на рабочем столе

Статус: реализовано 2026-10-09 — срезы (3), (2), окно и трей, (4); проверено пользователем 2026-10-09, закрыта.

## Задача

Видеть и управлять озвучкой ответов Claude Code: пауза, стоп, перемотка в любое место,
пропуск сообщения; история последних сообщений (в запросе — три; см. решение о хвосте).

## Согласованные решения

- Озвучку по-прежнему синтезирует демон `claude-tts` (пакет `melderan/claude-code-tts`,
  режим `queue`, `speech_unit: sentence`); сам пакет не меняем. — согласовано 2026-10-09
- Звук демона перехватывается: демон запускается с нашим каталогом первым в `PATH`,
  `detect_player()` (`claude_code_tts/audio.py:46`) находит нашу обёртку `paplay` вместо
  системной. Обёртка забирает копию WAV предложения и сразу завершается; в динамик звук
  выводит наш плеер. — согласовано 2026-10-09
- Следствие: пауза демона (`claude-tts pause`) больше не управляет звуком, управление — у
  плеера. Обёртка завершается сразу, убивать демону нечего; пауза лишь задерживает синтез
  между предложениями (`play_sentences`, `daemon.py:740`). — проверено по коду 2026-10-09
- Интерфейс — приложение рабочего стола Cinnamon: окно и значок в трее; плеер и
  интерфейс в одном процессе, процесс работает всегда, окно открывается по клику.
  — согласовано 2026-10-09
- Управление: `[ prev ] [ pause ] [ play|stop ] [ next ]` и ползунок перемотки.
  Сообщения встают в очередь, новое не перебивает текущее. «Пропустить» = `stop` текущего,
  затем `next` — к следующему сообщению, если оно есть; `prev` — к предыдущему.
  Доигравшее само сообщение сменяется следующим из очереди автоматически; после `stop`
  плеер стоит до `play` или `next`. — согласовано 2026-10-09
- Плеер — Python 3 + PyGObject из системных пакетов: GTK 3, GStreamer (`playbin`),
  значок в трее — XApp. Без виртуального окружения и pip. — выбрано пользователем
  2026-10-09; зависит от версий GTK и GStreamer в дистрибутиве
- Кнопки — решение controller'а 2026-10-09, на проверке у пользователя:
  `pause` — пауза и продолжение с той же позиции; на паузе автопереход не идёт.
  `play|stop` — `stop` останавливает и сбрасывает позицию на начало текущего сообщения,
  автоперехода нет; `play` после `stop` играет текущее сообщение с начала.
  `next` / `prev` — следующее / предыдущее сообщение с начала, играть (в том числе после
  `stop`); сообщение, покинутое по `next`/`prev`, считается прослушанным, если оно уже
  синтезировано целиком; незаконченное остаётся непрослушанным (уточнено ревью 2026-10-09).
  Ползунок — позиция внутри текущего сообщения (до склейки — по полученным предложениям),
  состояние (играет / пауза) не меняет. Очистка буфера останавливает звук и удаляет все
  сообщения, включая хвост; новые предложения приходят как обычно.
  Окно закрывается в трей, процесс не завершается.
  Выход из плеера — пункт «Выход» в меню значка (правая кнопка); непроигранное
  возвращается в буфер. Плееру нужен апплет трея (в Cinnamon он есть); без него окно
  доступно только при запуске с `--show`.
- О сообщении окно показывает время, первые слова текста (8 слов, длиннее — с «…»; без
  текста — проект), длительность, позицию. — согласовано 2026-10-09; первые слова вместо
  проекта — сказано пользователем 2026-10-09, проект виден в строке активной сессии
- `/tts-on` (`tts-toggle.sh on`) рядом с запуском демона проверяет плеер и, если он не
  запущен, запускает его свёрнутым в трей. Окно с плеером открывается кликом по иконке.
  — согласовано 2026-10-09
- Обёртка `paplay` только кладёт файл в буфер — каталог, за которым следит плеер. Сама
  звук не играет ни при каких условиях: плеер остановлен или не запущен — файлы
  копятся в буфере. В окне — кнопка очистки всего буфера. — согласовано 2026-10-09
- Единица буфера — сообщение целиком. Пока сообщение синтезируется, в буфере лежат его
  предложения; появилась склейка в `speech_history` — плеер заменяет их одним файлом
  сообщения. — согласовано 2026-10-09
- Хвост проигранного — 5 последних сообщений: с началом проигрывания 6-го удаляется
  самое старое. Хвост заменяет историю из трёх сообщений из задачи; `prev` ведёт назад
  не дальше хвоста. История демона нужна плееру только как признак конца сообщения и
  источник служебных данных. Непроигранные сообщения хвостом не ограничены, их убирает
  только очистка буфера. — согласовано 2026-10-09
- Синтез по предложениям (`speech_unit: sentence`) остаётся: первый звук — после первого
  предложения. Конец сообщения — появление склейки в `~/.claude-tts/speech_history` и
  строки в `handy_analysis.db` (`save_history()`, `daemon.py:829`). До этого перемотка —
  в пределах полученных предложений, после — по всему файлу. Склейка заменяет предложения
  без сдвига позиции: она состоит из тех же файлов подряд, тишину перед первым предложением
  демон вписывает в его файл до передачи обёртке (`daemon.py:747–757`); позиция в склейке
  равна сумме длительностей сыгранных предложений. Отказ от синтеза по
  предложениям (`speech_unit: message`) — запасной вариант, если признак конца не
  сработает. — согласовано 2026-10-09

## Цепочка взаимодействия

Согласовано 2026-10-09:

```
хук Stop / PostToolUse
  → claude-tts speak ──(JSON в ~/.claude-tts/queue)──→ демон claude-tts   [не меняем]
                                                        │
             ┌──────────────────────────────────────────┤
             │ (1) paplay <wav> на каждое предложение   │ (2) по окончании сообщения:
             ▼                                          ▼     склейка в speech_history
   обёртка paplay (наша)                                      + строка в handy_analysis.db
             │ (3) файл в буфере                        │
             ▼                                          │
   приложение-плеер (трей + окно) ◄─────────────────────┘
             │
             ▼
   динамик (PulseAudio/PipeWire)

/tts-on → tts-toggle.sh → запуск демона (с обёрткой в PATH) и плеера в трее
```

## Контракты

### (1) Демон → обёртка paplay

Задан демоном, принимаем как есть (`daemon_play_audio`, `daemon.py:532`):

```
paplay <wav>
<wav> = /tmp/tts_queue_{session_id}_{token}_s{i}.wav   # предложение i прохода token
      | /tmp/tts_announce.wav                          # объявление при смене голоса
      | /tmp/tts_daemon_announce.wav                   # объявление демона
```

Код возврата демон не читает; пока процесс жив, демон считает, что звук играет. Текста
предложения, общего числа предложений и сигнала конца сообщения в вызове нет. После
склейки демон удаляет файлы предложений.

### (2) История демона → плеер

Пишет демон (`save_speech_wav`, `handy.py`), принимаем как есть:

```
~/.claude-tts/speech_history/tts-{created_at:.3f}-{session_id[:40]}.wav   # склейка сообщения

~/.claude-tts/handy_analysis.db
  speech_history(id, file_name, created_at, session_id, project, persona,
                 text /* первые 500 символов */, speed, tone, duration_seconds)
```

Порядок записи: сначала копия WAV в каталог, затем строка в базе. Склейка пишется, когда
сообщение доиграло, когда сорвался синтез (сказанное считается сообщением) и когда пауза
пришлась на самый конец; не пишется при отмене через bridge (`cancelled`) и когда не
сказано ни одного предложения. Демон держит 50 последних записей и удаляет старые файлы
сам.

### (3) Обёртка paplay → плеер (буфер)

Согласовано 2026-10-09:

```
paplay [опции] <wav>                      # опции не используются

буфер:  $XDG_RUNTIME_DIR/tts-player/inbox/
файл:   {recv_ns}_{basename(<wav>)}       # recv_ns — время приёма, наносекунды: порядок
запись: cp <wav> inbox/.{имя}.part  →  mv inbox/.{имя}.part inbox/{имя}   # атомарно
exit:   0 — файл в буфере; 1 — копия не удалась
сбой:   сообщение в stderr и в journal: logger -t tts-player-paplay
```

Демон запускает плеер с `stdout/stderr=DEVNULL` и код возврата не читает, поэтому
единственный след сбоя обёртки — journal (`journalctl -t tts-player-paplay`).
Согласовано 2026-10-09.

Плеер читает только файлы без точки в начале имени; забранное из `inbox` дальше
принадлежит плееру. Объявления (`tts_announce.wav`, `tts_daemon_announce.wav`) обёртка
в буфер не кладёт.
Буфер в tmpfs: при выходе из системы стирается, на диск не пишется.

### (4) `tts-toggle.sh` → плеер

Согласовано 2026-10-09:

```
tts-toggle.sh on  →  tts-player --tray   # запуск свёрнутым в трей, вывод отвязан (как у демона)
  уже запущен            → exit 0, второй экземпляр не стартует
  нет графической сессии → exit 1, сообщение в stderr

tts-toggle.sh off →  tts-player stop     # команда запущенному плееру
  плеер запущен          → текущее сообщение остановлено, буфер цел, плеер в трее; exit 0
  плеер не запущен       → exit 0, ничего не делает

признак «запущен»: flock на $XDG_RUNTIME_DIR/tts-player/player.lock, держит процесс плеера
```

Как `tts-player stop` доходит до запущенного экземпляра (сокет, сигнал) — внутреннее
дело плеера: обе стороны — один исполняемый файл.

Реализация (срез (4), 2026-10-09): `tts-toggle.sh` зовёт не `tts-player` напрямую, а
`tts-player-hook on|off` из репозитория:

```
tts-player-hook on   (только режим queue)
  демона нет / PID не claude-tts       → PATH=daemon-bin:$PATH claude-tts daemon start
  демон без daemon-bin первым в PATH   → отвязанный claude-tts daemon restart (до 15 с у занятого
                                          демона — таймаут хука 5 с)
  плеер не запущен                     → setsid tts-player --tray, лог $XDG_RUNTIME_DIR/tts-player/player.log
  плеер запущен                        → tts-player play (SIGUSR2): из stopped/idle играет текущее
tts-player-hook off  → tts-player stop (SIGUSR1)
tts-player stop|play без XDG_RUNTIME_DIR или без плеера → exit 0
```

`tts-player play` из `/tts-on` — решение controller'а 2026-10-09 по итогам ревью, на проверке
у пользователя: без него после `/tts-off` во время игры новые ответы копились бы молча до
кнопки в окне.

## Открытые вопросы

- Сообщение без склейки: отмена через bridge, падение демона, синтез без единого
  предложения — признак конца не придёт. Пока (план `2026-10-09-tts-player-intake`)
  запасной признак — новый `token`: текущее сообщение без непроигранных предложений
  считается доигравшим, как только появилось более позднее. Срез (2) решает, остаётся ли
  это правило рядом со склейкой.
  Решено в срезе (2), 2026-10-09: правило остаётся рядом со склейкой — демон говорит
  сообщения строго по одному, и сообщение без склейки иначе не закончится.
- Пауза или перезапуск демона посреди сообщения: продолжение идёт новым проходом с
  новым `token` (`stream_message(start_index=…)`, `daemon.py:1333`), а склейка в истории
  содержит только предложения последнего прохода. Плеер, заменивший предложения
  склейкой, потеряет начало сообщения.
  Решено в срезе (2), 2026-10-09: для плеера это два сообщения (новый `token`); склейка
  сопоставляется с самым поздним сообщением сессии и совпадает со вторым по длительности,
  первое доигрывается по предложениям — начало не теряется.
- Плеер упал посреди сообщения. Решение 2026-10-09, согласовано
  пользователем: штатный выход (`stop`, SIGTERM) возвращает непроигранные предложения в
  `inbox/`, файлы хвоста удаляет; остатки `store/` после падения стартующий плеер удаляет
  с WARNING — без сохранённого состояния проигранное не отличить, а повтор пяти старых
  сообщений хуже потери. Цена: непрослушанное при падении плеера теряется.
- Срез (2): очередь удаляет файлы любых предложений своих сообщений; склейку из
  `~/.claude-tts/speech_history` (её держит демон) нужно копировать в `store/`, а не
  подставлять по ссылке. Решено в срезе (2): `attach` копирует в `store/`.
- Пропадание вывода звука (PulseAudio/PipeWire): согласовано 2026-10-09 — ошибка
  ресурса не продвигает очередь, то же предложение повторяется через 2 с; ошибка самого
  файла — пропуск.
- Между файлом склейки и строкой в базе есть промежуток: плеер, увидевший файл, ждёт
  строку или читает служебные данные позже. Решено в срезе (2): `history.py` повторяет
  чтение каждые 0,2 с до 5 с, затем WARNING.
- Обёртка демона и `~/.claude/hooks/bin/paplay` (flock-обёртка режима direct) — два
  разных `paplay`; обёртке демона нужен свой каталог, иначе демон с `hooks/bin` в `PATH`
  найдёт чужую. Решено: каталог `daemon-bin/` в репозитории.
- Демон уже запущен без обёртки в `PATH`: `claude-tts daemon start` его не трогает
  (`tts-toggle.sh`), и звук идёт мимо плеера, пока демон не перезапущен. Решено в срезе
  (4): `tts-player-hook on` перезапускает такой демон отвязанно. Цена: ответ, который
  `/tts-on` озвучивает сразу, при этом перезапуске может прозвучать мимо плеера или
  потеряться — повторить `/tts-on` через несколько секунд.
- Сопоставление предложений с записью истории: имя файла истории содержит сессию, но не
  `token`; держится на том, что демон говорит сообщения строго по одному.
- Как обёртка оказывается в `PATH` демона на каждом пути запуска: `tts-toggle.sh`,
  `claude-tts daemon restart`, перезапуск по control-сообщению, systemd-сервис
  (`daemon install`). Частично решено в срезе (4): через `tts-player-hook` — да;
  перезапуск по control-сообщению сохраняет окружение (`execv`). Ручной
  `claude-tts daemon restart`, перезапуск при обновлении пакета и systemd-сервис обёртку
  теряют — звук мимо плеера до следующего `/tts-on`.
- Плеер вышел («Выход») или упал, а озвучка включена: демон пишет в `inbox/` (tmpfs, ОЗУ)
  без ограничения, около 300 МБ на час речи; следующий `/tts-on` проиграет накопленное.
  Нужен ли предел или очистка при `/tts-on`.
- Сейчас обёртки `~/.claude/hooks/bin/piper` и `paplay` в режиме queue не действуют:
  `PATH` демона их не содержит. Нужна ли пауза между предложениями из `piper`-обёртки.
