# TTS Player: текст демону по предложениям

Статус: реализовано (2026-10-17).

## Задача (со слов пользователя, согласовано)

- Демон озвучивает не ту дорожку, которую слушают: новый ответ открытой сессии уходил в синтез
  целиком, и демон занимался последней дорожкой списка, пока пользователь слушает другую.
- Новым дорожкам — только первое предложение (холодный старт при переключении минимален),
  остальные остаются неозвученными.
- Озвучивается дорожка, которую слушают. Переключился посреди воспроизведения — озвучка прежней
  останавливается, начинается озвучка новой.
- Механизм предложил пользователь: демон и так озвучивает по предложениям — плеер отдаёт по
  одному, при переключении договаривается последнее отданное, а нового не отдаётся. Плеер
  должен помнить, на каком предложении остановился, чтобы вернуться с того же места; запись
  о том, что уже попало в озвучку, хранится вместе с сообщениями.

## Решение

- Почему не отмена в демоне: у `claude-tts` отмена задачи есть только у HTTP-моста
  (`/stop`, выключен в `config.json`), и для задач из файловой очереди она ненадёжна: между
  предложениями `audio_pid` пуст, и `/stop` не трогает идущий поток. Подача по одному
  предложению правок демона не требует.
- Счётчик (`sentence_count_worker`) отдаёт позиции начал всех предложений (`starts`), той же
  `split_sentences`, что и демон; кусок `text[k_i:k_{i+1}]` демон делит ровно на одно
  предложение. Заменил `rest_at`.
- У сообщения `pieces` — какое предложение текста какой задачей демона отдано; сохраняется в
  `messages.json`. Файл задачи-предложения приходит с индексом 0, его место в тексте — по
  `pieces`. `head_task` прежнего файла читается как `pieces = {head_task: 0}`.
- Кому что отдаётся (`Player._feed`, из `_changed`):
  - текущей дорожке, пока она играет или на паузе, — следующее неотданное предложение, когда у
    демона нет в работе другого её предложения;
  - новому ответу открытой сессии при ведущем плеере (⏩ нажата, свой текст не звучит) — только
    первое; он, как раньше, начинается сам в idle;
  - следующей за текущей отложенной дорожке при ведущем плеере — первое (прежнее «первое
    предложение заранее»); сама она от него не начинается.
- Голос предложений: у нового ответа — поля его задачи хука, как раньше у всей задачи; у
  отложенного и после переозвучки — текущий голос из `config.json`.
- Готовность предложения: файл пришёл, доигран и удалён при выходе, запись задачи не удалась
  (`skipped`, без повтора в этом запуске) или демон взял более позднюю задачу, а файла нет (сбой
  синтеза — без повтора). Сообщение по предложениям завершено, когда готово каждое.
- Голос при начале дорожки отличается от того, которым отдавались предложения, — отданное
  выбрасывается, отдача с первого предложения заново.
- Без деления текста — как раньше, разом: счётчика нет; счётчик сломался (`on_broken` —
  ждавшие деления ответы уходят разом); дорожку начали до ответа счётчика.

## Открытые вопросы

- Паузы между предложениями: следующее отдаётся демону, только когда пришло предыдущее, —
  если синтез предложения дольше звучания предыдущего (очень короткие фразы), между ними будет
  тишина. Проверяется на слух; если мешает — держать у демона два предложения текущей дорожки.
