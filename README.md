# TTS Player

Плеер озвучки Claude Code для Linux: окно в трее с очередью и историей озвученных
реплик, кнопками play/pause и пропуска. Проигрывает звук, который синтезирует демон
`claude-tts` в режиме `queue`.

Дизайн: [docs/superpowers/specs/2026-10-09-tts-player-design.md](docs/superpowers/specs/2026-10-09-tts-player-design.md).

## Как подключается

```
Claude Code hook -> claude-tts speak --from-hook (HOME = hook-home)
  -> tts-player (хранит текст, пишет задачу в ~/.claude-tts/queue)
  -> claude-tts daemon -> daemon-bin/paplay (обёртка) -> tts-player (трей, история)
```

- Хуки `~/.claude/hooks/speak-response.sh` и `speak-intermediate.sh` запускают
  `claude-tts speak --from-hook` с `HOME=$XDG_RUNTIME_DIR/tts-player/hook-home`. В очередь
  демона хук больше не пишет: готовая задача ложится в `hook-home/.claude-tts/queue/`.
- Плеер забирает задачу оттуда, сохраняет текст сообщения и сам кладёт задачу демону в
  `~/.claude-tts/queue` (`"source": "tts-player"`). В эту очередь пишет только плеер.
- Демон синтезирует и вызывает `paplay`. Обёртка `daemon-bin/paplay` берёт id задачи из
  `~/.claude-tts/playback.json` и кладёт файл в `inbox/` плеера с id в имени; по id плеер
  находит сообщение. Файл с неизвестным или чужим id удаляется.
- Каталог `hook-home` создаёт и чистит плеер при старте: в нём ссылки на `config.json` и
  `sessions.d/` из `~/.claude-tts` и файл `daemon.heartbeat`, который плеер обновляет раз в 10 с,
  пока жив настоящий демон. Если плеер не запущен, heartbeat в `hook-home` нет, и хук молча
  пропускает речь - так задумано.

Демон ищет проигрыватель `paplay` через `PATH`. `bin/tts-player-hook` запускает демон
с `daemon-bin/` первым в `PATH` (или перезапускает, если он работает без обёртки), поэтому
вместо системного `paplay` звук попадает в буфер плеера.

## Установка

Нужен `jq`: им обёртка `daemon-bin/paplay` читает id задачи демона из `~/.claude-tts/playback.json`.

```bash
ln -s ~/Programs/TTSReader/bin/tts-player ~/.local/bin/tts-player
ln -s ~/Programs/TTSReader/bin/tts-player-hook ~/.local/bin/tts-player-hook
```

В `~/.claude/hooks/tts-toggle.sh` (подробно - «Переход на сессии» ниже):

- ветка `on`, режим `queue`: вместо `claude-tts daemon start/status` одна строка
  `tts-player-hook on "$CLAUDE_CODE_SESSION_ID" "$PWD"`;
- ветка `off`: `tts-player session remove "$CLAUDE_CODE_SESSION_ID"`.

### Правка хуков речи

В `~/.claude/hooks/speak-response.sh` и `speak-intermediate.sh` меняется строка запуска:
добавляется переменная `HOOK_HOME` и префикс `HOME="$HOOK_HOME"` перед `exec`
(остальное, включая `PATH=... exec claude-tts speak --from-hook ...`, как было):

```bash
HOOK_HOME="${XDG_RUNTIME_DIR:-/run/user/$(id -u)}/tts-player/hook-home"
HOME="$HOOK_HOME" PATH="$(dirname "$0")/bin:$PATH" exec claude-tts speak --from-hook --hook-type stop
```

(`--hook-type post_tool_use` - во втором скрипте.)

### Переход на новую цепочку

Старый и новый порядок несовместимы в обе стороны: новый плеер со старыми хуками молчит
(задачи без `source` дают файлы с id `unknown`, плеер их удаляет), старый плеер с новыми
хуками молчит (без `hook-home` хук речь пропускает). Поэтому шаги идут одним заходом:

1. Слить обновление в `~/Programs/TTSReader` - безопасно, пока работает старый плеер: он
   держит старый код в памяти.
2. Дослушать очередь: непрослушанный звук старого плеера при переходе теряется.
3. Снять копии хуков:
   ```bash
   cd ~/.claude/hooks
   cp -p speak-response.sh speak-response.sh.bak-2026-10-09
   cp -p speak-intermediate.sh speak-intermediate.sh.bak-2026-10-09
   ```
4. Закрыть плеер: «Выход» в меню трея.
5. Поправить строку запуска в обоих хуках (см. «Правка хуков речи»).
6. Сразу запустить плеер: `tts-player --tray`.
7. Проверить `$XDG_RUNTIME_DIR/tts-player/player.log` после ответа Claude: есть строки
   `task …` и `playing …`, нет `чужое предложение … (задача unknown)`.

Откат - в таком порядке:

1. Закрыть плеер: «Выход» в меню трея.
2. Вернуть хуки из копий:
   ```bash
   cd ~/.claude/hooks
   cp -p speak-response.sh.bak-2026-10-09 speak-response.sh
   cp -p speak-intermediate.sh.bak-2026-10-09 speak-intermediate.sh
   ```
3. Вернуть прежний код плеера в `~/Programs/TTSReader` (коммит до слияния).
4. Удалить сохранённые сообщения нового формата:
   `rm "$XDG_RUNTIME_DIR/tts-player/messages.json"`.
5. Запустить плеер: `tts-player --tray`.

### Переход на сессии

Озвучка включается не флагом `/tmp/claude-tts.on`, а списком сессий плеера (см. «Список сессий»):
гейт хука спрашивает `tts-player session has`. Файлы вне репозитория правятся так:

- `~/.claude/hooks/tts-gate.sh`: вместо проверки флага `/tmp/claude-tts.on` и сравнения с ним
  `session_id` - `tts-player session has <session_id>` (выход 0 - озвучивать, иначе хук молча
  выходит; так же при пустом `session_id`); иначе гейт запускает хук как
  `CLAUDE_TTS_SESSION=<session_id> exec <скрипт хука>` (настройки сессий `claude-tts` ведутся по
  UUID), вход хука идёт в скрипт без изменений;
- `~/.claude/hooks/tts-toggle.sh`: `on` - `tts-player-hook on "$CLAUDE_CODE_SESSION_ID" "$PWD"`
  (демон, плеер и сессия в списке), `off` - `tts-player session remove "$CLAUDE_CODE_SESSION_ID"`;
  флаг `/tmp/claude-tts.on` не пишется и не снимается;
- `~/.claude/hooks/tts-command.sh`: на `/tts-on` речь предыдущего ответа сразу, с
  `CLAUDE_TTS_SESSION=<UUID>` сессии из входа хука;
- описания `~/.claude/commands/tts-on.md` и `tts-off.md`: убрать упоминание флага
  `/tmp/claude-tts.on`, сказать «сессия добавляется в список плеера» и «убирается из него».

Порядок:

1. Слить обновление в `~/Programs/TTSReader`.
2. Убедиться, что плеер запущен после слияния среза (14) (есть `control/` в
   `$XDG_RUNTIME_DIR/tts-player`); иначе перезапустить. Список сессий перезапуск переживает.
3. Поправить хуки по списку выше (`tts-player-hook` и `tts-player` - в `PATH`) и удалить старый
   флаг: `rm -f /tmp/claude-tts.on` (его мог записать прежний `/tts-on`).
4. В каждой сессии, которую нужно озвучивать, выполнить `/tts-on`: пока сессии нет в списке,
   её хуки молчат.

Команды остановки и продолжения звука из CLI удалены: у них не осталось вызывающих. Звук ставит
на паузу кнопка окна.

## Команды

- `tts-player --tray` - плеер в трее (так его запускает хук);
- `tts-player --show` - запуск с открытым окном (у уже работающего плеера окно открывает щелчок по значку в трее);
- `tts-player --no-gui` - без окна, только приём и воспроизведение;
- `tts-player session add UUID CWD`, `session remove UUID` - добавить сессию в список плеера и убрать
  из него (см. «Список сессий»);
- `tts-player session has UUID` - спросить, в списке ли сессия запущенного плеера (см.
  «Список сессий»): выход 0 - да, 1 - нет; вывода нет; неверные аргументы - usage в stderr, выход 2;
- `/tts-on`, `/tts-off` - включить и выключить озвучку сессии (`on` зовёт `tts-player-hook on UUID CWD`: демон, плеер и `session add`; `off` - `tts-player session remove UUID`);
- меню трея «Выход» - закрыть плеер.

## Список сессий

Плеер ведёт список сессий Claude Code, которые озвучивает, в
`$XDG_RUNTIME_DIR/tts-player/sessions.json`:
`{"active": "<uuid>" | null, "sessions": [{"id": "<uuid>", "project": "<последний компонент cwd>"}, …]}`.
`active` - одна из `sessions` или `null`. Файл пишет только плеер, атомарно; читают его
`tts-player session has` и через неё - гейт хука Claude Code.

`tts-player session has UUID` отвечает кодом выхода, ничего не печатает и не создаёт файлов:

- `0` - UUID есть в `sessions` и плеер запущен (блокировка экземпляра взята);
- `1` - UUID нет в списке, файла нет, файл битый, плеер не запущен или `XDG_RUNTIME_DIR` не задан;
- `2` - неверные аргументы, usage в stderr.

`tts-player session add UUID CWD` и `tts-player session remove UUID` список не меняют сами: кладут запрос
в `$XDG_RUNTIME_DIR/tts-player/control/` (файл `<ns>.json`, пишется атомарно), плеер забирает его, меняет
список и пишет в журнал `session add UUID` / `session remove UUID` (только при настоящем изменении).
Проект в списке - последний компонент `CWD`; первая добавленная сессия становится `active`. Сообщение в
stdout, выход 0:

- «сессия передана плееру» (`add`) / «сессия передана плееру на удаление» (`remove`) - запрос записан,
  плеер запущен;
- «сессия уже в списке» (`add`) / «сессия не в списке» (`remove`) - список уже в нужном состоянии,
  запрос не пишется, но только при пустой очереди `control/`; иначе запрос пишется всегда (в очереди
  может лежать запрос, который это состояние изменит);
- «плеер не запущен — сессия добавится при его запуске» / «… уберётся при его запуске» - запрос лежит в
  `control/` и выполнится на старте плеера.

Выход 1 - `XDG_RUNTIME_DIR` не задан или запрос не записан (причина в stderr); выход 2 - неверные
аргументы, usage в stderr.

Список лежит в runtime-каталоге: после перезагрузки или выхода пользователя он исчезает, а без
запущенного плеера `has` отвечает `1` и по файлу прошлого запуска. Перезапуск плеера список
переживает: плеер при старте читает `sessions.json`, и сессия остаётся в нём без нового `add`.

## Сессии в плеере

У каждой сессии из списка своё сообщение-хвост (очередь): сообщения одной сессии не смешиваются с
другими.

- Синтезируется только активная сессия: её задачи хука уходят в очередь демона сразу, пока не
  звучит свой текст. Задача неактивной сессии и задача активной во время своего текста
  откладываются (в журнале `task <id> <uuid> deferred`): в демон не уходят, сообщение с текстом
  ждёт в очереди своей сессии. Задача сессии не из списка удаляется
  (`task <id> <uuid> dropped: not in list`).
- Отложенное сообщение озвучивается, когда воспроизведение доходит до него: оно уходит в демон
  тогда, а не при получении.
- Переключение активной сессии (журнал `session select <uuid>`): звук останавливается, текущим
  становится первое непрослушанное сообщение новой активной. Окно с выбором сессии - следующий срез.
- Очистка буфера удаляет сообщения и файлы активной сессии; сессия остаётся в списке, остальные
  не затрагиваются.
- `session remove` удаляет сообщения сессии и их файлы в `store/`; убранная активная сессия оставляет
  список без активной, пока другую не выберут.
- Список сообщений окна показывает очередь активной сессии.
- Перезапуск плеера сохраняет сообщения по сессиям (`messages.json`, отложенные помечены): сообщения
  активной играют по автовоспроизведению, отложенные остаются неотправленными, пока воспроизведение не
  дойдёт до них.

## Сообщения, переозвучка, перезапуск

- Плеер хранит текст сообщения и голос (персона, скорость), которым оно поставлено в
  демон, и переозвучивает сообщение через демон, играя его по мере синтеза: если звука нет
  (запись задачи не удалась, демон ничего не прислал, файлы потеряны) - по команде
  пользователя (play/pause, предыдущее/следующее, выбор и play), автовоспроизведение такое
  сообщение пропускает; или голос/скорость отличаются от активной персоны - при начале
  проигрывания. Сообщение сессии со своей персоной переозвучивается активной персоной.
  Пока задача сообщения ещё стоит в очереди демона, переозвучки нет: оно прозвучит прежним
  голосом, следующий play переозвучит.
- Перезапуск плеера: сообщения переживают его (`$XDG_RUNTIME_DIR/tts-player/messages.json`
  и файлы в `store/`), но не перезагрузку и не выход из сеанса. Прослушанные сохраняются
  только текстом, без файлов; непрослушанные - с файлами. Сообщение, прерванное выходом,
  продолжается с недоигранного предложения.
- Обновление плеера с переходом на новую цепочку - см. «Переход на новую цепочку».
- Известное ограничение: задача демона, по которой не пришло ни одного предложения (демон не
  работает, пустой текст), оставляет сообщение «растущим»: статус playing без звука, чужие
  звуки остаются приглушёнными, пока не придёт предложение следующей задачи. Так же
  «растущим» может остаться последнее непрослушанное сообщение после перезапуска плеера:
  склейка, которую демон записал, пока плеер не работал, к нему не привязывается.

## Окно

Сверху вниз:

- ряд служебных значков: слева шестерёнка «Настройки», корзина «Очистить буфер»,
  выключение озвучки и «Озвучить свой текст» (см. «Свой текст»); справа выключатель
  «Автовоспроизведение» (см. «Настройки плеера»);
- список сообщений: щелчок по строке только выбирает сообщение (звук останавливается, позиция в начало, статус «остановлено»); играть оно начинает по play/pause;
- ползунок позиции текущего сообщения;
- ряд управления: слева время `позиция / длина`, справа кнопки `[⏮] [⏵/⏸] [⏭]`.

Кнопка play/pause при воспроизведении ставит паузу, на паузе продолжает с того же места; после
остановки или конца сообщения играет текущее (доигранное - уступает следующему), без текущего -
первое непрослушанное. Кнопки stop в окне нет.

## Свой текст

Значок с карандашом «Озвучить свой текст» в ряду наверху окна открывает экран: поле ввода,
ползунок, время `позиция / длина` и кнопка `[⏵/⏸]`. Текст озвучивается голосом
активной персоны `claude-tts` по предложениям: звук начинается с первого, следующие
синтезируются, пока играет предыдущее, и ползунок растёт по мере синтеза. Изменённый текст
озвучивается заново: прежний звук и синтез отменяются. Если синтез или воспроизведение не
удались, текст ошибки виден под ползунком; после правки текста он исчезает. Причины ищут в
stderr плеера (`player.log`), в `~/.claude-tts/daemon.log` и в
`~/.claude-tts/workers/sherpa-worker.log`.

- Озвученная дорожка принадлежит только этому экрану: в список сообщений главного экрана она
  не попадает и в истории не остаётся (файлы - в `tts-player/text/` под `$XDG_RUNTIME_DIR`,
  удаляются при смене текста, выходе и следующем запуске).
- Один звук за раз: play своего текста ставит главный плеер на паузу, и пока свой текст
  звучит, главный сам ничего не начинает (автовоспроизведение ждёт). После конца или паузы
  своего текста главный остаётся на паузе до команды пользователя.
- Стрелка назад возвращает на главный экран и ставит свой текст на паузу, в том числе пока
  первое предложение ещё синтезируется (синтез идёт дальше); продолжает кнопка play на экране
  «Свой текст».

Синтез идёт отдельным процессом в Python-окружении `claude-tts`:
`--tts-python FILE` - его интерпретатор (по умолчанию
`~/.local/share/uv/tools/claude-code-tts/bin/python`). Экран есть только с окном, не с `--no-gui`.

## Настройки голоса

Шестерёнка в ряду значков наверху окна открывает экран настроек: голос (персона
`claude-tts`), скорость и хвост очереди (см. «Настройки плеера»). «Сохранить» меняет голос и
скорость для всех проектов:

- выбранный голос становится активной персоной в `~/.claude-tts/config.json`;
- одна скорость записывается всем персонам;
- сбрасываются переопределения проектов (`project_personas`) и сессий (`persona`, `speed`
  в `~/.claude-tts/sessions.d/*.json`) - иначе они перекрыли бы выбор.

Голос действует на реплики, поставленные в очередь после сохранения (персона фиксируется
при постановке в очередь); уже пришедшие переозвучиваются при проигрывании, если голос или
скорость у них другие (см. «Сообщения, переозвучка, перезапуск»). Скорость - на всё, что ещё не озвучено, включая реплики, уже
стоящие в очереди (демон читает скорость персоны при синтезе).
«Сохранить» оставляет экран настроек открытым; итог - узкий блок внизу экрана: зелёный
«Настройки сохранены» или красный текст ошибки. Если настройки `claude-tts` не прочитались,
блок сразу показывает причину, голос и скорость недоступны, а «Сохранить» пишет только хвост.
Стрелка назад закрывает экран без сохранения.
Каталог настроек меняет `--tts-config-dir DIR` (по умолчанию `~/.claude-tts`).

## Выключение озвучки

Третий значок наверху окна (после корзины и шестерёнки) выключает озвучку - то же, что `/tts-off`
для озвучиваемой сессии: плеер берёт ID сессии из флага и зовёт хук `<хук> off`. Пока озвучка
выключена (флага нет или он пуст), значок неактивен; состояние обновляется при показе окна и
каждые 250 мс, пока окно видно. После перехода на сессии (см. «Переход на сессии») хук `off`
зовёт `tts-player session remove`; флаг больше не пишется, и значок остаётся неактивным, пока
оконный срез не превратит его в «Завершить активную сессию». Хук `off` зовёт `tts-player`,
поэтому он должен быть в `PATH` плеера (иначе в логе код 127).

- `--tts-flag FILE` - флаг озвучки (по умолчанию `/tmp/claude-tts.on`);
- `--tts-off-hook FILE` - хук выключения (по умолчанию `~/.claude/hooks/tts-toggle.sh`).

## Настройки плеера

Файл `$XDG_CONFIG_HOME/tts-player/settings.json` (без `XDG_CONFIG_HOME` -
`~/.config/tts-player/settings.json`), читается при старте:
`{"tail": <1-20>, "autoplay": <true|false>, "duck": <0-100>}`. Нет файла - хвост 5,
автовоспроизведение включено, приглушение до 30 %.

- `tail` - сколько последних начатых сообщений держит очередь; после уменьшения лишние уходят
  постепенно, с каждым новым начатым хвост становится на одно сообщение короче;
- `autoplay: false` - плеер сам не начинает ни следующее сообщение, ни новое, пришедшее в
  тишине: после конца сообщения он останавливается на следующем. Играть начинает по команде:
  play/pause, prev/next; щелчок по строке только выбирает сообщение.

- `duck` - до скольких процентов их громкости плеер приглушает чужие аудиопотоки, пока сам
  говорит (см. «Приглушение чужих звуков»).

Значения меняются из окна, сразу пишутся в файл и применяются без перезапуска:

- выключатель «Автовоспроизведение» справа в ряду значков - `autoplay`; не удалось записать
  файл - причина в логе, выключатель возвращается в прежнее положение;
- поле «Хвост очереди» (1-20) на экране настроек - `tail`, пишется кнопкой «Сохранить»;
- поле «Приглушать другие звуки до, %» (0-100, шаг 5) там же - `duck`, пишется той же кнопкой.

Другой файл задаёт `--settings-file FILE`.

## Приглушение чужих звуков

Пока плеер говорит (состояние playing), громкость чужих аудиопотоков (музыка, видео) снижается
до `duck` % от текущей; на паузе, после остановки и при выходе - возвращается как была.
Значение задаётся в окне: «Приглушать другие звуки до, %» (0-100, по умолчанию 30).

- `100` - приглушение выключено, потоки не трогаются;
- потоки, уже звучащие в начале речи, глушатся сразу; появившиеся во время речи - когда им
  исполнится 5 с (короткие звуки, например уведомления, не трогаются);
- исходные громкости записываются в `duck.json` в каталоге `tts-player` под `$XDG_RUNTIME_DIR`;
  если плеер упал, не восстановив громкость, при следующем запуске она возвращается по этому файлу;
- приглушённый поток, закончившийся во время речи, звуковой сервер (WirePlumber) запоминает
  приложению сниженную громкость. Для приложения плеер держит пару (исходная, сниженная)
  громкость: она действует, пока жив его приглушённый поток, а когда последний исчез,
  записывается по имени приложения в `duck-orphans.json` (тот же каталог). Новый поток
  приложения (появившийся после начала речи или после записи пары: новая вкладка, перезапущенный
  трек) с громкостью, равной сниженной (±1), во время речи глушится сразу от исходной громкости
  пары, вне речи ему возвращается исходная; все подходящие потоки одного прохода обрабатываются.
  С другой громкостью (пользователь поправил сам) поток не трогается, а запись снимается.
  Потоки, звучавшие до начала речи, пара не трогает. Вне речи плеер проверяет потоки раз в 2 с в
  течение 10 минут после последнего изменения записей, дальше - при начале речи; файл
  переживает перезапуск плеера, но не выход из сеанса;
- нужна утилита `pactl` (PulseAudio или PipeWire-pulse); без неё приглушение не работает,
  предупреждение пишется в лог плеера (`player.log`) один раз за начало речи, остальное - как
  обычно;
- громкость остаётся сниженной и между предложениями растущего сообщения, и пока звуковой выход
  недоступен (статус при этом playing).

## Проверка вручную

```bash
python3 -m unittest discover -s tests
command -v tts-player tts-player-hook
# в сессии Claude Code:
/tts-on     # первый раз: демон перезапущен с обёрткой, плеер в трее, сессия в списке
/tts-off    # сессия убрана из списка, её хуки молчат
/tts-on     # сессия снова в списке
```

- Первый `/tts-on` перезапускает демон, если он работал без обёртки: ответ, пришедший во время
  перезапуска, может прозвучать мимо плеера - повторите `/tts-on` через несколько секунд.
- Перезапуск занимает до 15 с и нужен только занятому демону; демон с обёрткой первым в `PATH` не трогается.
- `tts-player session has "$CLAUDE_CODE_SESSION_ID"; echo $?` - 0 после `/tts-on`, 1 после `/tts-off`.
- Плеер стартует в трее с закрытым окном; чтобы открыть окно, щёлкните по значку в трее
  (`tts-player --show` показывает окно только при запуске нового экземпляра).
- Ошибки запуска плеера - в логах ниже.

## Логи

- `$XDG_RUNTIME_DIR/tts-player/player.log` - вывод плеера;
- `$XDG_RUNTIME_DIR/tts-player/daemon-restart.log` - перезапуск демона;
- `journalctl -t tts-player-paplay` - обёртка `paplay`;
- `~/.claude-tts/daemon.log` - демон.
