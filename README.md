# TTS Player

Плеер озвучки Claude Code для Linux: окно в трее с очередью и историей озвученных
реплик, кнопками play/pause и пропуска. Проигрывает звук, который синтезирует демон
`claude-tts` в режиме `queue`.

Дизайн: [docs/superpowers/specs/2026-10-09-tts-player-design.md](docs/superpowers/specs/2026-10-09-tts-player-design.md).

## Как подключается

```
claude-tts daemon -> daemon-bin/paplay (обёртка) -> буфер плеера -> tts-player (трей, история)
```

Демон ищет проигрыватель `paplay` через `PATH`. `bin/tts-player-hook` запускает демон
с `daemon-bin/` первым в `PATH` (или перезапускает, если он работает без обёртки), поэтому
вместо системного `paplay` звук попадает в буфер плеера. Плеер хранит историю реплик.

## Установка

```bash
ln -s ~/Programs/TTSReader/bin/tts-player ~/.local/bin/tts-player
ln -s ~/Programs/TTSReader/bin/tts-player-hook ~/.local/bin/tts-player-hook
```

В `~/.claude/hooks/tts-toggle.sh`:

- ветка `on`, режим `queue`: вместо `claude-tts daemon start/status` одна строка `tts-player-hook on`;
- ветка `off`, когда флаг этой сессии снят: `tts-player-hook off`.

## Команды

- `tts-player --tray` - плеер в трее (так его запускает хук);
- `tts-player --show` - запуск с открытым окном (у уже работающего плеера окно открывает щелчок по значку в трее);
- `tts-player --no-gui` - без окна, только приём и воспроизведение;
- `tts-player stop` - остановить текущий звук, плеер остаётся;
- `tts-player play` - то же, что play/pause из остановленного и пустого состояния (при включённом и выключенном автовоспроизведении): продолжает текущее с курсора, доигранное текущее уступает следующему, без текущего начинает первое непрослушанное; играющее и на паузе не трогает;
- `/tts-on`, `/tts-off` - включить и выключить озвучку сессии (хук зовёт `tts-player-hook on|off`; `on` у работающего плеера зовёт `tts-player play`);
- меню трея «Выход» - закрыть плеер.

## Окно

Сверху вниз:

- ряд служебных значков: слева шестерёнка «Настройки», корзина «Очистить буфер» и
  выключение озвучки; справа выключатель «Автовоспроизведение» (см. «Настройки плеера»);
- список сообщений: щелчок по строке только выбирает сообщение (звук останавливается, позиция в начало, статус «остановлено»); играть оно начинает по play/pause;
- ползунок позиции текущего сообщения;
- ряд управления: слева время `позиция / длина`, справа кнопки `[⏮] [⏵/⏸] [⏭]`.

Кнопка play/pause при воспроизведении ставит паузу, на паузе продолжает с того же места; после
остановки или конца сообщения играет текущее (доигранное - уступает следующему), без текущего -
первое непрослушанное. Кнопки stop в окне нет: остановить звук - `tts-player stop`.

## Настройки голоса

Шестерёнка в ряду значков наверху окна открывает экран настроек: голос (персона
`claude-tts`), скорость и хвост очереди (см. «Настройки плеера»). «Сохранить» меняет голос и
скорость для всех проектов:

- выбранный голос становится активной персоной в `~/.claude-tts/config.json`;
- одна скорость записывается всем персонам;
- сбрасываются переопределения проектов (`project_personas`) и сессий (`persona`, `speed`
  в `~/.claude-tts/sessions.d/*.json`) - иначе они перекрыли бы выбор.

Голос действует на реплики, поставленные в очередь после сохранения (персона фиксируется
при постановке в очередь). Скорость - на всё, что ещё не озвучено, включая реплики, уже
стоящие в очереди (демон читает скорость персоны при синтезе).
«Сохранить» оставляет экран настроек открытым; итог - узкий блок внизу экрана: зелёный
«Настройки сохранены» или красный текст ошибки. Если настройки `claude-tts` не прочитались,
блок сразу показывает причину, голос и скорость недоступны, а «Сохранить» пишет только хвост.
Стрелка назад закрывает экран без сохранения.
Каталог настроек меняет `--tts-config-dir DIR` (по умолчанию `~/.claude-tts`).

## Выключение озвучки

Третий значок наверху окна (после корзины и шестерёнки) выключает озвучку - то же, что `/tts-off`
для озвучиваемой сессии: плеер берёт ID сессии из флага и зовёт хук `<хук> off`. Пока озвучка
выключена (флага нет или он пуст), значок неактивен; состояние обновляется при показе окна и
каждые 250 мс, пока окно видно. Хук зовёт `tts-player-hook`, поэтому он должен быть в `PATH` плеера:
иначе флаг снимется, а звук не остановится (в логе код 127).

- `--tts-flag FILE` - флаг озвучки (по умолчанию `/tmp/claude-tts.on`);
- `--tts-off-hook FILE` - хук выключения (по умолчанию `~/.claude/hooks/tts-toggle.sh`).

## Настройки плеера

Файл `$XDG_CONFIG_HOME/tts-player/settings.json` (без `XDG_CONFIG_HOME` -
`~/.config/tts-player/settings.json`), читается при старте:
`{"tail": <1-20>, "autoplay": <true|false>, "duck": <0-100>}`. Нет файла - хвост 5,
автовоспроизведение включено, приглушение до 30 %.

- `tail` - сколько последних начатых сообщений держит очередь; после уменьшения лишние уходят
  постепенно, с каждым новым начатым хвост становится на одно сообщение короче;
- `autoplay: false` - плеер сам не начинает ни следующее сообщение, ни новое, пришедшее в
  тишине: после конца сообщения он останавливается на следующем. Играть начинает по команде:
  play/pause, prev/next, `tts-player play`; щелчок по строке только выбирает сообщение.

- `duck` - до скольких процентов их громкости плеер приглушает чужие аудиопотоки, пока сам
  говорит (см. «Приглушение чужих звуков»).

Значения меняются из окна, сразу пишутся в файл и применяются без перезапуска:

- выключатель «Автовоспроизведение» справа в ряду значков - `autoplay`; не удалось записать
  файл - причина в логе, выключатель возвращается в прежнее положение;
- поле «Хвост очереди» (1-20) на экране настроек - `tail`, пишется кнопкой «Сохранить»;
- поле «Приглушать другие звуки до, %» (0-100, шаг 5) там же - `duck`, пишется той же кнопкой.

Другой файл задаёт `--settings-file FILE`.

## Приглушение чужих звуков

Пока плеер говорит (состояние playing), громкость чужих аудиопотоков (музыка, видео) снижается
до `duck` % от текущей; на паузе, после остановки и при выходе - возвращается как была.
Значение задаётся в окне: «Приглушать другие звуки до, %» (0-100, по умолчанию 30).

- `100` - приглушение выключено, потоки не трогаются;
- потоки, уже звучащие в начале речи, глушатся сразу; появившиеся во время речи - когда им
  исполнится 5 с (короткие звуки, например уведомления, не трогаются);
- исходные громкости записываются в `duck.json` в каталоге `tts-player` под `$XDG_RUNTIME_DIR`;
  если плеер упал, не восстановив громкость, при следующем запуске она возвращается по этому файлу;
- приглушённый поток, закончившийся во время речи, звуковой сервер (WirePlumber) запоминает
  приложению сниженную громкость; плеер записывает исходную и сниженную громкость по имени
  приложения в `duck-orphans.json` (тот же каталог) и исправляет задним числом: новый поток
  этого приложения (не звучавший в тот момент, например новая вкладка) с громкостью, равной
  сниженной (±1), во время речи глушится сразу от исходной громкости, вне речи ему возвращается
  исходная; с другой громкостью (пользователь поправил сам) - не трогается; уже звучавшие
  потоки приложения запись не затрагивает. Вне речи плеер проверяет потоки раз в 2 с в течение
  10 минут после последнего изменения записей, дальше - при начале речи; файл переживает перезапуск плеера, но не выход из сеанса;
- нужна утилита `pactl` (PulseAudio или PipeWire-pulse); без неё приглушение не работает,
  предупреждение пишется в лог плеера (`player.log`) один раз за начало речи, остальное - как
  обычно;
- громкость остаётся сниженной и между предложениями растущего сообщения, и пока звуковой выход
  недоступен (статус при этом playing).

## Проверка вручную

```bash
python3 -m unittest discover -s tests
command -v tts-player tts-player-hook
# в сессии Claude Code:
/tts-on     # первый раз: демон перезапущен с обёрткой, плеер в трее
/tts-off    # звук остановлен
/tts-on     # воспроизведение продолжено
```

- Первый `/tts-on` перезапускает демон, если он работал без обёртки: ответ, пришедший во время
  перезапуска, может прозвучать мимо плеера - повторите `/tts-on` через несколько секунд.
- Перезапуск занимает до 15 с и нужен только занятому демону; демон с обёрткой первым в `PATH` не трогается.
- После `/tts-off` повторный `/tts-on` продолжает остановленное воспроизведение.
- Плеер стартует в трее с закрытым окном; чтобы открыть окно, щёлкните по значку в трее
  (`tts-player --show` показывает окно только при запуске нового экземпляра).
- Ошибки запуска плеера - в логах ниже.

## Логи

- `$XDG_RUNTIME_DIR/tts-player/player.log` - вывод плеера;
- `$XDG_RUNTIME_DIR/tts-player/daemon-restart.log` - перезапуск демона;
- `journalctl -t tts-player-paplay` - обёртка `paplay`;
- `~/.claude-tts/daemon.log` - демон.
