# TTS Player

Плеер озвучки Claude Code для Linux и macOS: окно в трее с очередью и историей озвученных
реплик, кнопками play/pause и ⏩ автовоспроизведения. Проигрывает звук, который синтезирует
демон `claude-tts` в режиме `queue`.

Дизайн: [docs/superpowers/specs/2026-10-09-tts-player-design.md](docs/superpowers/specs/2026-10-09-tts-player-design.md),
установка на двух ОС: [docs/superpowers/specs/2026-10-19-tts-player-macos-install-design.md](docs/superpowers/specs/2026-10-19-tts-player-macos-install-design.md).

## Установка

Одной командой, без клона:

```bash
curl -fsSL https://raw.githubusercontent.com/lav45/TTSReader/master/install.sh | bash
```

Скрипт клонирует репозиторий в `~/.local/share/tts-player` (при повторном запуске — `git pull
--ff-only` там же) и запускает `install.sh` из клона; ввод (пароль `sudo`) он берёт из терминала.
Другой каталог и другие аргументы — после `bash -s --`:

```bash
curl -fsSL https://raw.githubusercontent.com/lav45/TTSReader/master/install.sh \
    | bash -s -- --dir ~/Programs/TTSReader
```

Нужен `git`: на macOS он приходит с Command Line Tools (`xcode-select --install`, их же требует
Homebrew), на Linux скрипт ставит его через apt. Из уже клонированного репозитория — то же самое
без curl: `./install.sh` (`--dir` тогда не нужен).

Каталог после установки не переносить: ссылки в `~/.local/bin` и хуки ведут в него.

Нужны: на Linux — apt (Debian, Ubuntu, Mint; на других дистрибутивах скрипт называет пакеты, а
ставить их придётся самим), на macOS — [Homebrew](https://brew.sh) и macOS 12.3 или новее.
`install.sh` ставит системные пакеты (GTK 3, GStreamer, PyGObject, ffmpeg), uv, `claude-tts` из
форка, на чистой машине — штатный установщик `claude-tts` (Piper, голос по умолчанию,
`~/.claude-tts/config.json`), движок sherpa-onnx и модель Supertonic 3 (русский голос). Затем он
настраивает `claude-tts` под плеер, делает ссылки `~/.local/bin/tts-player` и `tts-player-hook`,
вписывает хуки в `~/.claude/settings.json` (копия — `settings.json.bak-<дата>`) и перезапускает
работающие демон и плеер. Повторный запуск — обновление: сделанные шаги пропускаются.
`--claude-tts-source <источник uv>` ставит `claude-tts` из другого места, например из локального
клона форка: `--claude-tts-source "git+file://$HOME/Programs/claude-code-tts@lav45"`.

Python с PyGObject, который нашёл `install.sh`, записан в `.python` в корне репозитория (файл
не в git); `bin/tts-player` и `bin/tts-player-hook` запускаются им, без файла — `python3` из `PATH`.
Хуки зовут `claude-tts` из `PATH`: `~/.local/bin` должен быть в `PATH` терминала, из которого
запущен Claude Code (`uv tool update-shell`; `install.sh` предупредит, если его там нет).
Демон наследует тот же `PATH` и ищет в нём `ffmpeg`: им скорость персоны Supertonic задаёт
`atempo` (на быстром синтезе Supertonic смазывает концы слов). Нет `ffmpeg` в `PATH` — демон молча
синтезирует сразу на скорости персоны; `install.sh` ставит `ffmpeg` и предупреждает, если его там не видно.

На macOS нет паузы других плееров (MPRIS) и паузы на диктовку (`pactl`): эти настройки в окне
скрыты. Значок — в строке меню (`Gtk.StatusIcon`); на Linux — XApp, если библиотека есть.

## Как подключается

```
Claude Code ──хук Stop / PostToolUse──> tts-player-hook stop | post-tool-use
   └─> claude-tts speak --from-hook  (CLAUDE_TTS_QUEUE_DIR = <runtime>/tts-player/hook-queue)
         └─> tts-player: хранит текст, кладёт задачу в ~/.claude-tts/queue ("source": "tts-player")
               └─> claude-tts daemon: синтез, проигрыватель из player_command
                     └─> tts-player sink <wav> (CLAUDE_TTS_MESSAGE_ID) ─> inbox/ ─> tts-player
Claude Code ──SessionStart / SessionEnd──> tts-player-hook start | end ─> список сессий плеера
```

- `<runtime>` — каталог состояния на время сеанса: `$XDG_RUNTIME_DIR`, на macOS — `$TMPDIR`
  (`tts_player/runtime_dir.py`). Ниже он записан как `$XDG_RUNTIME_DIR`.
- Хуки речи пропускаются молча, если сессии нет в списке запущенного плеера. Иначе
  `claude-tts speak --from-hook` кладёт задачу не в очередь демона, а в `hook-queue/` плеера
  (переменная `CLAUDE_TTS_QUEUE_DIR` форка). Если демон не жив, `speak` речь пропускает сам.
- Плеер забирает задачу, сохраняет текст сообщения и сам кладёт задачу демону в
  `~/.claude-tts/queue` (`"source": "tts-player"`). В эту очередь пишет только плеер.
- Демон синтезирует и зовёт проигрыватель из `player_command` в `~/.claude-tts/config.json` —
  `["<~/.local/bin/tts-player>", "sink"]` (настройка форка, читается на каждое предложение,
  перезапуск демона не нужен). `tts-player sink` не играет, а кладёт файл в `inbox/` плеера с id
  сообщения из `CLAUDE_TTS_MESSAGE_ID` в имени; по id плеер находит сообщение. Файл с неизвестным
  или чужим id удаляется.
- Хук `UserPromptSubmit` (`tts-player-hook prompt`) для сессии из списка добавляет в контекст тон
  голоса: `claude-tts handy tone-context`.

### Демон из форка

`claude-tts` ставится не из upstream (`melderan/claude-code-tts`), а из форка
`lav45/claude-code-tts`, клон — `~/Programs/claude-code-tts`. В ветке `lav45` лежат правки,
которых в upstream нет:

| Коммит | Зачем |
|---|---|
| `feat: sherpa loads Supertonic models` | загрузка модели Supertonic 3 (ru+en) для персоны `supertonic-3`; без неё воркер sherpa не стартует, и демон говорит запасным английским голосом piper |
| `feat: a Supertonic persona's speed goes through ffmpeg atempo` | модель Supertonic синтезирует на скорости 1.0, скорость персоны задаёт `ffmpeg atempo`: на быстром синтезе Supertonic смазывает последние слова |
| `fix: a Stop does not speak again a reply a subagent's PostToolUse took from the file` | хук `post_tool_use` субагента (у него session_id и транскрипт основной сессии), сработавший в ту же секунду, когда ответ лёг в транскрипт, озвучивал ответ из файла, а `stop` того же хода — ещё раз из своего входа: в плеере две одинаковые дорожки с разницей в секунду |
| `feat: an external player takes the daemon's audio through config.json player_command` | `player_command` и `CLAUDE_TTS_MESSAGE_ID`: демон отдаёт звук плееру, а не подменённому `paplay` в `PATH` (на macOS демон ищет `afplay` и подмену не находил); `CLAUDE_TTS_QUEUE_DIR`: хук кладёт задачу в очередь плеера, а не в очередь демона |

`install.sh` берёт ветку `lav45` с GitHub, поэтому новые правки форка доходят до других машин
только после `git push origin lav45`. Обновление на новый релиз upstream — слиянием тега в
`lav45`, затем `install.sh` (с `--claude-tts-source` локального клона, пока правки не отправлены).

## Команды

- `tts-player --tray` - плеер в трее (так его запускает хук);
- `tts-player --show` - запуск с открытым окном (у уже работающего плеера окно открывает щелчок по значку в трее; щелчок поднимает окно поверх остальных, даже если оно уже открыто);
- `tts-player --no-gui` - без окна, только приём и воспроизведение; открыть сессию без окна нечем,
  поэтому играют только новые ответы сессии, оставшейся открытой с прошлого запуска с окном;
- `tts-player session add UUID CWD`, `session remove UUID` - добавить сессию в список плеера и убрать
  из него (см. «Список сессий»);
- `tts-player session clear UUID CWD` - убрать сессию после `/clear`; если она была открытой, открытой станет
  новая сессия из того же каталога (см. «Список сессий»);
- `tts-player session has UUID` - спросить, в списке ли сессия запущенного плеера (см.
  «Список сессий»): выход 0 - да, 1 - нет; вывода нет; неверные аргументы - usage в stderr, выход 2;
- `tts-player sink [опции] WAV` - проигрыватель демона (`player_command`): кладёт файл в `inbox/`
  плеера и сразу выходит; опции (`afplay -r` на macOS) не читаются; сбой - stderr и syslog
  (`journalctl -t tts-player-sink`), выход 1;
- `tts-player-hook start | end | stop | post-tool-use | prompt` - хуки Claude Code `SessionStart`,
  `SessionEnd`, `Stop`, `PostToolUse`, `UserPromptSubmit`; JSON хука приходит на stdin
  (`tts_player/hook_command.py`). `start`: гейт режима - в `~/.claude-tts/config.json` `mode` не
  `queue` (нет файла или поля - `direct`), тогда одна строка в `hook.log` и больше ничего; иначе
  поднимает демон (`claude-tts daemon start`) и плеер (`tts-player --tray`), если их нет, и добавляет
  сессию в список. `end` убирает сессию; при `reason` = `clear` (`/clear`) - `session clear` (без
  `cwd` - ошибка, выход 1). Вывода в stdout у `start` и `end` нет, статус - в
  `$XDG_RUNTIME_DIR/tts-player/hook.log` (первой строкой каждого вызова - событие:
  `<дата время> start|end <UUID> source=… reason=… cwd=…`), ошибка - в stderr с выходом 1.
  `stop`, `post-tool-use`, `prompt` для сессии не из списка запущенного плеера молча выходят с 0,
  иначе зовут `claude-tts` (см. «Как подключается») и отдают его stdout и код;
- меню трея «Выход» - закрыть плеер.

## Список сессий

Плеер ведёт список сессий Claude Code, которые озвучивает, в
`$XDG_RUNTIME_DIR/tts-player/sessions.json`:
`{"active": "<uuid>" | null, "sessions": [{"id": "<uuid>", "project": "<последний компонент cwd>"}, …]}`.
`active` - одна из `sessions` или `null`. Файл пишет только плеер, атомарно; читают его
`tts-player session has` и через неё - гейт хука Claude Code. Сессию добавляет хук `SessionStart`
(`tts-player-hook start`), убирает хук `SessionEnd` (`tts-player-hook end`); из окна сессию не
убрать (см. «Очистка сессии»).

`tts-player session has UUID` отвечает кодом выхода, ничего не печатает и не создаёт файлов:

- `0` - UUID есть в `sessions` и плеер запущен (блокировка экземпляра взята);
- `1` - UUID нет в списке, файла нет, файл битый, плеер не запущен или `XDG_RUNTIME_DIR` не задан;
- `2` - неверные аргументы, usage в stderr.

`tts-player session add UUID CWD` и `tts-player session remove UUID` список не меняют сами: кладут запрос
в `$XDG_RUNTIME_DIR/tts-player/control/` (файл `<ns>.json`, пишется атомарно), плеер забирает его, меняет
список и пишет в журнал `session add UUID` / `session remove UUID` (только при настоящем изменении);
`session clear UUID CWD` пишет `session clear UUID`, а замена открытой сессии - `session replace UUID`.
Проект в списке - последний компонент `CWD`; новая сессия добавляется закрытой (`active` не меняется,
открывает её пользователь в окне).

Сообщение в stdout, выход 0:

- «сессия передана плееру» (`add`) / «сессия передана плееру на удаление» (`remove`) - запрос записан,
  плеер запущен;
- «сессия уже в списке» (`add`) / «сессия не в списке» (`remove`) - список уже в нужном состоянии,
  запрос не пишется, но только при пустой очереди `control/`; иначе запрос пишется всегда (в очереди
  может лежать запрос, который это состояние изменит);
- «плеер не запущен — сессия добавится при его запуске» / «… уберётся при его запуске» - запрос лежит в
  `control/` и выполнится на старте плеера.

Выход 1 - `XDG_RUNTIME_DIR` не задан или запрос не записан (причина в stderr); выход 2 - неверные
аргументы, usage в stderr.

`tts-player session clear UUID CWD` - запрос хука `SessionEnd` с `reason` = `clear`: сообщения и выходы те
же, что у `remove`, сессия `UUID` убирается так же. Если она была открытой (активной), плеер запоминает `CWD`,
и следующая новая сессия с таким же `cwd` в `session add` (её `SessionStart` приходит сразу за `SessionEnd`)
сразу открывается, как после щелчка по её папке; ожидание снимают пришедшая замена и щелчок по закрытой папке (ожидание
бывает, только пока открытой сессии нет). Выход и `/resume` открытую сессию новой не передают. Замена срабатывает,
если `cwd` новой сессии совпадает с `cwd` из `SessionEnd` очищенной; совпадают ли они после `cd` внутри
сессии - не проверено (открытый вопрос спеки); не совпали - новую сессию открывают щелчком в окне.

Список лежит в runtime-каталоге: после перезагрузки или выхода пользователя он исчезает, а без
запущенного плеера `has` отвечает `1` и по файлу прошлого запуска. Перезапуск плеера список
переживает: плеер при старте читает `sessions.json`, и сессия остаётся в нём без нового `add`.

## Сессии в плеере

У каждой сессии из списка своё сообщение-хвост (очередь): сообщения одной сессии не смешиваются с
другими.

- Активная сессия - открытая папка в окне (см. «Окно»); открыта одна или ни одной. При нажатой
  кнопке ⏩ открытая сессия играет подряд и только вперёд: после конца - следующее по порядку; за
  последним плеер ждёт, и пришедший ответ играет сам он, а не более ранние непрослушанные. При
  отжатой ⏩ сообщение, доиграв, останавливает плеер: следующее, даже лежащее в списке, запускает
  пользователь. Отжатая кнопка делает открытую папку по синтезу такой же, как закрытая:
  задачи хука откладываются (`task <id> <uuid> deferred`) и уходят в демон по play/pause или
  щелчку. История отжатой папки копится, пока папка открыта, и режется до `tail` при её закрытии.
  Дорожки отжатой папки видны и играют по щелчку. Закрытые только
  собирают сообщения. Новая сессия добавляется закрытой;
  исключение - `/clear`: если очищена была открытая сессия, новая из того же каталога открывается
  сама (журнал `session clear <uuid>`, затем `session add <uuid>` и `session replace <uuid>`).
- Синтезируется только активная сессия при нажатой ⏩: её новые ответы получают синтез сразу,
  пока не звучит свой текст. Задача неактивной сессии и задача активной во время своего текста
  откладываются (в журнале `task <id> <uuid> deferred`): в демон не уходят, сообщение с текстом
  ждёт в очереди своей сессии. Задача сессии не из списка удаляется
  (`task <id> <uuid> dropped: not in list`).
- Текст по предложениям: плеер отдаёт демону текст не целиком, а по одному предложению на
  задачу (журнал `piece <uuid> <номер>/<всего> <id задачи>`). Новому ответу открытой сессии - только
  первое предложение, чтобы дорожка зазвучала без ожидания синтеза. Дорожке, которую слушают
  (играет или стоит на паузе), - следующее предложение, как только демон прислал предыдущее:
  у демона в работе не больше одного её предложения. Остальные дорожки ждут неозвученными.
  Щелчок по другой дорожке: прежняя больше не получает предложений (демон договаривает одно,
  уже начатое), новая получает их по одному. Вернувшись к дорожке, плеер продолжает с первого
  предложения, которого демону ещё не отдавал: что какой задачей отдано, он помнит у каждой
  дорожки (`messages.json`, переживает перезапуск плеера). Предложение, которое демон не
  озвучил (сбой синтеза) или задача которого не записалась, пропускается без повтора.
  Пока ⏩ нажата и дорожка играет или на паузе, следующая за ней отложенная тоже получает
  первое предложение, но сама от него не начинается (после ⏹ - тоже). Где кончается каждое
  предложение, считает счётчик предложений той же функцией `split_sentences`, что и демон;
  пока он не ответил, щелчок по дорожке отдаёт её текст целиком, как раньше, а если счётчик
  недоступен (строка WARNING в журнале), текст всех ответов уходит целиком.
- Отложенное сообщение озвучивается, когда воспроизведение доходит до него: предложения уходят
  в демон тогда, а не при получении. Пока ничего не озвучено, длительность сообщения в списке -
  `0:00`.
- Голос сменился между предложениями дорожки: при её начале уже отданное прежним голосом
  выбрасывается, и текст отдаётся заново с первого предложения новым голосом.
- Длина истории сессии - `tail` (см. «Настройки плеера»): столько последних сообщений хранит
  сессия без фокуса - закрытая папка или открытая при нажатой ⏩ в ожидании нового ответа после
  конца последнего. Лишние - прослушанные, непрослушанные, отложенные - удаляются вместе с файлами,
  самые старые первыми: сразу при закрытии и открытии папки, конце последнего сообщения, смене
  `tail` и запуске плеера, а потом с каждым новым ответом. Выбранное (текущее) сообщение
  места в `tail` не занимает и не удаляется: остаются `tail` последних и оно, если старше.
  Пока сообщение открытой сессии играет, стоит на паузе или выбрано щелчком, ответы копятся
  без ограничения; позади текущего начатые ограничены тем же `tail`. Копятся и ответы открытой
  сессии, отданные демону в этом запуске плеера, которые ещё синтезируются и до которых дойдёт
  автопереход (новее текущего): пачка ответов быстрее синтеза не теряет ранние. При отжатой ⏩
  ответы открытой сессии копятся всё время, пока она открыта.
  Восстановленные после перезапуска сообщения этого не дают.
- Открытие сессии (журнал `session select <uuid>`): звук останавливается, текущего сообщения нет -
  ничего не играет до play/pause, щелчка по сообщению или нового сообщения сессии. Закрытие
  открытой (журнал `session close <uuid>`): звук останавливается, активной сессии нет, её
  сообщения остаются.
- «Очистить сообщения активной сессии» удаляет сообщения и файлы активной сессии; сессия остаётся в списке, остальные
  не затрагиваются.
- `session remove` (журнал `session remove <uuid>`) удаляет сообщения сессии и их файлы в `store/`; убранная активная сессия оставляет
  список без активной, пока другую не выберут.
- Дорожки в окне видны только у открытой сессии.
- Перезапуск плеера сохраняет сообщения по сессиям (`messages.json`, отложенные помечены). При
  старте плеер сам ничего не играет: открытая папка ждёт нового ответа (текущего нет), её
  непрослушанные играют по play/pause или щелчку; отложенные остаются неотправленными, пока
  воспроизведение не дойдёт до них. При нажатой ⏩ новые ответы играют как обычно (с отжатой плеер сам их не начинает); новым считается и
  предложение задачи прошлого запуска, которое демон досинтезировал без плеера (лежит в
  `inbox/` при старте или приходит позже): при нажатой ⏩ его сообщение играет само.

## Сообщения, переозвучка, перезапуск

- Плеер хранит текст сообщения и голос (персона, скорость), которым оно поставлено в
  демон, и переозвучивает сообщение через демон, играя его по мере синтеза: если звука нет
  (запись задачи не удалась, демон ничего не прислал, файлы потеряны) - по команде
  пользователя (play/pause, выбор и play), автопереход такое
  сообщение пропускает; или голос/скорость отличаются от активной персоны - при начале
  проигрывания. Сообщение сессии со своей персоной переозвучивается активной персоной.
  Пока задача сообщения ещё стоит в очереди демона, переозвучки нет: оно прозвучит прежним
  голосом, следующий play переозвучит.
- Пауза или перезапуск демона посреди сообщения: новый проход синтеза начинается с
  оборванного предложения, и оно приходит дважды. Звучит одно: поздний проход заменяет ещё не
  звучавшее, а если прежнее уже звучит или прозвучало, пришедшее удаляется (в журнале
  `дубль предложения …`).
- Перезапуск плеера: сообщения переживают его (`$XDG_RUNTIME_DIR/tts-player/messages.json`
  и файлы в `store/`), но не перезагрузку и не выход из сеанса. Прослушанные сохраняются
  только текстом, без файлов, и после старта снова отложены: остаются прослушанными, а
  автопереход их озвучивает, как отложенные (первое предложение - заранее, пока играет
  предыдущее), и не пропускает; непрослушанные - с файлами. Сообщение, прерванное выходом,
  при следующем проигрывании продолжается с недоигранного предложения.
- Предложение с id задачи `unknown` (демон не передал `CLAUDE_TTS_MESSAGE_ID`: текущего
  сообщения не было) относится к задаче своего прохода синтеза: у прохода
  случайная метка в имени файла (`…_<метка>_sN.wav`), и если у сообщения уже есть предложение с
  ней, плеер добавляет туда же (в журнале `предложение без id задачи отнесено к задаче …`).
  Без такой метки - чужое, файл удаляется.
- Конец сообщения: плеер считает, на сколько предложений демон разделит текст, той же функцией
  `claude-tts` (`split_sentences`, процесс в окружении `--tts-python`, один запрос на
  сообщение; число сохраняется в `messages.json`). Сообщение кончилось, когда у его задачи
  пришли все предложения - сразу после последнего; пустой текст кончается сразу. Запасной
  признак - предложение следующей задачи: по нему кончается сообщение, если счётчик недоступен
  (в журнале одна строка `счётчик предложений недоступен (…)`) или демон прислал не все
  предложения.
- Обновление плеера с переходом на новую цепочку - см. «Переход на новую цепочку».
- Известное ограничение: сообщение остаётся «растущим» - статус playing без звука, другие плееры
  остаются на паузе, пока не придёт предложение следующей задачи, - если у его задачи
  демон прислал не все предложения (демон не работает, сбой синтеза) или счётчик предложений
  недоступен. Без счётчика так остаются и задача с пустым текстом, и последнее сообщение, за
  которым нет следующего ответа. Такая задача открытой сессии держит её очередь
  при нажатой ⏩ необрезанной до tail (с отжатой очередь копится и так), пока не придёт следующий ответ (только в том запуске плеера, в котором
  она отдана демону).
- Обновление `claude-tts` при работающем прежнем процессе демона: плеер считает предложения
  новой версией `split_sentences`, демон делит текст старой, и до перезапуска демона деление
  может разойтись.

## Окно

Сверху вниз:

- ряд служебных значков: слева шестерёнка «Настройки», корзина «Очистить сообщения активной
  сессии» (см. «Очистка сессии»), справа значок документа «Озвучить свой текст» (см. «Свой текст»);
- дерево сессий, как папки с файлами:
  - заголовок папки - `▸`/`▾`, значок закрытой/открытой папки, `<проект> · <первые 8 символов id>`;
    открытая - жирным. Щелчок по закрытой открывает её сессию (она
    становится активной, прежняя открытая закрывается), по открытой - закрывает (активной нет,
    звук останавливается); см. «Сессии в плеере»;
  - дорожки открытой сессии - под заголовком с отступом: первые слова текста (без текста -
    проект), справа время прихода и длительность. Щелчок по дорожке сразу её играет,
    без ▶: другая дорожка - с начала; текущая на паузе - дальше с места, остановленная или
    доигранная - с позиции курсора (в конце - с начала); по звучащей щелчок ничего не меняет;
- ползунок позиции текущего сообщения;
- ряд управления: слева время `позиция / длина`, справа кнопки `[⏹]`, `[⏵/⏸]` и за ними крайняя
  справа кнопка-переключатель `[⏩]` автовоспроизведения; кнопок «назад» и «вперёд» нет - дорожку
  выбирают щелчком по строке.

Кнопка ⏩ решает, что плеер делает после конца дорожки. Нажата - играет следующая дорожка списка, а
если её нет, плеер ждёт, и новый ответ играет сам. Отжата - доигравшая дорожка останавливает плеер;
новые ответы откладываются и в синтез уходят по ▶, а история копится, пока папка открыта (см.
«Сессии в плеере»). Клик по ⏩ только переключает режим: звук не начинает и играющий не обрывает; накопленные
за время отжатой кнопки ответы остаются отложенными. Положение одно на плеер (смена сессии его не
меняет), сохраняется в `settings.json` и переживает перезапуск. Пока звучит свой текст, плеер сам
ничего не начинает при любом положении кнопки.

Доиграв последнюю дорожку списка, плеер при любом положении ⏩ встаёт так же, как по ⏹: выделение
строки снимается, ползунок в начале, время `0:00 / 0:00`. Доигранная дорожка прослушана; ▶ играет
последнюю дорожку списка с начала, щелчок - выбранную.

Кнопка play/pause при воспроизведении ставит паузу, на паузе продолжает с того же места; после
остановки или конца сообщения играет текущее (доигранное - уступает следующему), без выбранной
дорожки - последнюю (отложенная при этом озвучивается).

Кнопка ⏹ снимает курсор: звук обрывается, выделение строки снимается, время `0:00 / 0:00`; серая,
когда выбранной дорожки нет. Снятая дорожка прослушана, если её начинали и демон закончил её синтез,
- как при щелчке по другой строке. Дальше плеер в том же состоянии, что после конца последней
дорожки: при нажатой ⏩ ждёт, и следующий новый ответ играет сам с начала - в том числе тот, что
синтезируется сейчас, со своей следующей фразой; готовые непрослушанные ждут щелчка. Снятая
дорожка, даже если её фразы ещё приходят, сама не начинается - её слушают щелчком. При отжатой
⏩ новые ответы по-прежнему откладываются. При нажатой ⏩ история без выбранной дорожки режется до
`tail`, как после конца последней: старые строки, в том числе снятая, могут сразу исчезнуть; при
отжатой - копится, пока папка открыта (см. «Сессии в плеере»).

## Свой текст

Значок документа «Озвучить свой текст» справа в ряду наверху окна открывает экран: поле ввода,
ползунок, время `позиция / длина` и кнопка `[⏵/⏸]`. Текст озвучивается голосом
активной персоны `claude-tts` по предложениям: звук начинается с первого, следующие
синтезируются, пока играет предыдущее, и ползунок растёт по мере синтеза. Изменённый текст
озвучивается заново: прежний звук и синтез отменяются. Если синтез или воспроизведение не
удались, текст ошибки виден под ползунком; после правки текста он исчезает. Причины ищут в
stderr плеера (`player.log`), в `~/.claude-tts/daemon.log` и в
`~/.claude-tts/workers/sherpa-worker.log`.

- Озвученная дорожка принадлежит только этому экрану: в дерево сессий главного экрана она
  не попадает и в истории не остаётся (файлы - в `tts-player/text/` под `$XDG_RUNTIME_DIR`,
  удаляются при смене текста, выходе и следующем запуске).
- Один звук за раз: play своего текста ставит главный плеер на паузу, и пока свой текст
  звучит, главный сам ничего не начинает. После конца или паузы
  своего текста главный остаётся на паузе до команды пользователя.
- Переход на экран «Свой текст» - как переход в другую сессию: звучащий ответ встаёт на
  паузу, и пока экран открыт, сессии молчат - новые ответы и следующие дорожки сами не
  начинаются, даже если свой текст не звучит или уже доиграл.
- Стрелка назад возвращает на главный экран и ставит свой текст на паузу, в том числе пока
  первое предложение ещё синтезируется (синтез идёт дальше); продолжает кнопка play на экране
  «Свой текст». Открыта та же сессия, что была до перехода, ответ стоит на паузе там же,
  где его оставили; дальше плеер снова ведёт сам.

Синтез идёт отдельным процессом в Python-окружении `claude-tts`:
`--tts-python FILE` - его интерпретатор (по умолчанию
`~/.local/share/uv/tools/claude-code-tts/bin/python`); тем же интерпретатором, и с
`--no-gui`, работает счётчик предложений сообщений (см. «Сообщения, переозвучка,
перезапуск»). Экран есть только с окном, не с `--no-gui`.

## Настройки голоса

Шестерёнка в ряду значков наверху окна открывает экран настроек: голос (персона
`claude-tts`), скорость, хвост очереди, флажок «Ставить другие плееры на паузу» и поля
«Пауза до и после речи, мс» и «Продолжать после диктовки через, мс» (см. «Настройки плеера», «Пауза других плееров» и «Диктовка Claude Code»). «Сохранить» меняет голос и
скорость для всех проектов (хвост очереди, флажок и обе паузы идут в файл плеера, см. «Настройки плеера»):

- выбранный голос становится активной персоной в `~/.claude-tts/config.json`;
- одна скорость записывается всем персонам;
- сбрасываются переопределения проектов (`project_personas`) и сессий (`persona`, `speed`
  в `~/.claude-tts/sessions.d/*.json`) - иначе они перекрыли бы выбор.

Голос действует на реплики, поставленные в очередь после сохранения (персона фиксируется
при постановке в очередь); уже пришедшие переозвучиваются при проигрывании, если голос или
скорость у них другие (см. «Сообщения, переозвучка, перезапуск»). Скорость - на всё, что ещё не озвучено, включая реплики, уже
стоящие в очереди (демон читает скорость персоны при синтезе).
«Сохранить» оставляет экран настроек открытым; итог - узкая полоса во всю ширину у нижнего
края окна: «Настройки сохранены» на приглушённом зелёном (гаснет через 2 секунды) или
текст ошибки на красном (остаётся до закрытия экрана). Если настройки `claude-tts` не прочитались,
блок сразу показывает причину, голос и скорость недоступны, а «Сохранить» пишет только хвост очереди и флажок паузы других плееров (положение ⏩ оно переписывает таким, какое сейчас на кнопке).
Стрелка назад закрывает экран без сохранения.
Каталог настроек меняет `--tts-config-dir DIR` (по умолчанию `~/.claude-tts`).

## Очистка сессии

Корзина наверху окна (после шестерёнки) очищает сообщения активной сессии: тексты и файлы
удаляются, сессия остаётся в списке и собирает новые ответы. Без активной сессии корзина неактивна.
Кнопки «Завершить» нет: сессию убирает только хук `SessionEnd`, иначе живая сессия Claude Code
замолчала бы до перезапуска.

## Настройки плеера

Файл `$XDG_CONFIG_HOME/tts-player/settings.json` (без `XDG_CONFIG_HOME` -
`~/.config/tts-player/settings.json`), читается при старте:
`{"tail": <1-20>, "autoplay": <true|false>, "pause_others": <true|false>, "gap_ms": <0-10000>, "dictation_gap_ms": <0-10000>}`. Нет файла или ключа - хвост 5,
`autoplay` true (кнопка ⏩ нажата), `pause_others` true (флажок стоит), `gap_ms` и `dictation_gap_ms` 3000; значение `autoplay` или
`pause_others` не true/false - тоже true, `gap_ms` или `dictation_gap_ms` вне 0-10000 или не целое - 3000, строка в журнал. Неизвестные
ключи (например, от прежней версии плеера) игнорируются и при «Сохранить» не пишутся.

- `tail` - сколько сообщений хранит сессия без фокуса (закрытая папка или открытая при нажатой ⏩
  в ожидании нового ответа): лишние, самые старые, удаляются сразу, в том числе после уменьшения `tail`;
  текущее сообщение места в `tail` не занимает. Пока открытая сессия играет или стоит на паузе
  (или её ответы ещё синтезируются), сообщения копятся, а начатых позади текущего
  остаётся не больше `tail`; после уменьшения лишние начатые уходят постепенно, с каждым новым
  начатым на одно сообщение (см. «Сессии в плеере»). При отжатой ⏩ сообщения открытой сессии
  копятся, пока она открыта;
- `autoplay` - положение кнопки ⏩ (true - нажата), см. «Окно»;
- `pause_others` - ставить ли другие плееры на паузу, пока плеер говорит (true - ставить), см. «Пауза других плееров»;
- `gap_ms` - тишина в миллисекундах перед первым словом, если кто-то встал на паузу, и после речи, прежде чем
  другие продолжат, см. «Пауза других плееров»;
- `dictation_gap_ms` - через сколько миллисекунд после конца диктовки в Claude Code озвучка продолжается, см.
  «Диктовка Claude Code».

Значения меняются из окна, сразу пишутся в файл и применяются без перезапуска:

- поле «Хвост очереди» (1-20) на экране настроек - `tail`, пишется кнопкой «Сохранить»; вместе с ним она переписывает `autoplay` таким, какой он
  сейчас на кнопке ⏩;
- флажок «Ставить другие плееры на паузу» под ним - `pause_others`, при каждом открытии экрана показывает значение из
  файла, пишется той же кнопкой «Сохранить» и доступен, даже когда настройки голоса не прочитались;
- поле «Пауза до и после речи, мс» (0-10000, стрелки по 100) под флажком - `gap_ms`, при каждом открытии экрана показывает
  значение из файла, пишется той же кнопкой «Сохранить», доступно и при снятом флажке; новое значение действует со
  следующей паузы, идущий отсчёт не перезапускается;
- поле «Продолжать после диктовки через, мс» (0-10000, стрелки по 100, по умолчанию 3000) под ним - `dictation_gap_ms`,
  при каждом открытии экрана показывает значение из файла, пишется той же кнопкой «Сохранить»; новое значение
  действует со следующего отсчёта после диктовки;
- кнопка ⏩ в ряду управления - `autoplay`, пишется сразу по клику (`pause_others`, `gap_ms` и `dictation_gap_ms` в файле при этом не меняются). Если файл не записался, режим
  всё равно переключается до выхода из плеера, кнопка остаётся в новом положении, а ошибка идёт строкой
  WARNING в журнал (`player.log`); после перезапуска действует записанное в файле.

Другой файл задаёт `--settings-file FILE`.

## Пауза других плееров

Пока плеер говорит (состояние playing) и пока в Claude Code идёт диктовка (см. «Диктовка Claude Code»),
другие медиаплееры (музыка, видео в браузере) стоят на паузе. Плеер находит их по MPRIS на сессионной шине D-Bus (имена `org.mpris.MediaPlayer2.*`):
каждому, у кого `PlaybackStatus` равен `Playing`, он шлёт `Pause()` и запоминает его. Пауза
зависит от флажка «Ставить другие плееры на паузу» на экране настроек (`pause_others`,
по умолчанию стоит).

- флажок снят и сохранён, пока другие стоят на паузе, - они продолжают сразу, без тишины, а звук плеера
  идёт без тишины перед ним; пока флажок снят, плеер других не трогает и тишины перед звуком нет;
- флажок поставлен во время речи - действует со следующего начала речи, играющее не прерывается;
- если кто-то встал на паузу, первый звук плеера идёт через тишину «Пауза до и после речи» (`gap_ms`, по умолчанию 3 с):
  после видео нужно время переключить внимание на озвучку, иначе начало речи пропадает; если никто не играл - сразу. Окно в эту тишину выглядит как при игре, команды работают
  как обычно, отсчёт не перезапускается;
- свой текст (экран «озвучить свой текст») ставит других на паузу так же, но тишины перед ним
  нет;
- когда плеер замолчал (пауза, остановка, конец очереди), другие продолжают через ту же тишину `gap_ms`, если
  речь не началась снова; если началась - они так и стоят, пауза не повторяется. Между
  предложениями растущего сообщения и пока звуковой выход недоступен (плеер повторяет попытку)
  плеер считается говорящим: другие стоят;
- продолжаются только те, кого поставил на паузу плеер и кто всё ещё на паузе. Ручной запуск
  главнее: если пользователь сам запустил тот медиаплеер, пока шла речь, или тот остановился, или закрылся,
  TTS Player о нём забывает и не трогает;
- плееры, заигравшие во время речи, не ставятся на паузу - только игравшие в её начале;
- вызовы D-Bus асинхронные, с таймаутом 1 с: зависший плеер не останавливает окно. Плеер, у
  которого `Pause()` не прошёл, не запоминается и тишины перед звуком не вызывает; ошибка - строка в stderr;
- при выходе плеера другие продолжают сразу, без тишины;
- при падении плеера другие остаются на паузе: на диск ничего не пишется, продолжить некому.
  Файлы громкости прежней версии в `$XDG_RUNTIME_DIR/tts-player` плеер не читает и не удаляет,
  они уходят с выходом из сеанса;
- нужны сессионная шина D-Bus и плееры с MPRIS; звуковой сервер и его утилиты не требуются.
  Шины нет (macOS) - флажок и «Пауза до и после речи» на экране настроек скрыты.

## Диктовка Claude Code

`DictationWatch` следит за голосовым вводом Claude Code (удержание пробела): через `pactl subscribe`
и `pactl -f json list` он видит поток записи PipeWire, у клиента которого процесс запущен из
`~/.local/share/claude/versions/`. Запись других программ (`arecord`, звонки) не считается, имя потока не
смотрится. Плеер пишет в `player.log` «диктовка началась» и «диктовка кончилась» и молчит, пока в Claude Code
зажат пробел: и ответы, и свой текст (экран «Озвучить свой текст», см. «Свой текст»). Окно выглядит как при
воспроизведении (на кнопке ⏸). Через время из поля «Продолжать после диктовки через, мс» (`dictation_gap_ms`, по умолчанию 3 с) после отпускания речь продолжается с начала прерванного предложения;
если пробел зажат снова раньше, отсчёт идёт заново. Ответ, пришедший во время диктовки, ждёт конца диктовки и
этого времени, потом начинается. Другие плееры встают на паузу с началом диктовки, как с началом озвучки, даже если
TTS Player молчал или стоял на ⏸ (тишины перед звуком у одной диктовки нет); поставленные озвучкой остаются на паузе.
Продолжают они, когда плеер замолчал совсем: пробел отпущен, прошло «Продолжать после диктовки через», и если озвучивать
нечего - ещё «Пауза до и после речи»; если озвучка продолжилась, другие ждут её конца. ⏸ во время диктовки - обычная
пауза: после диктовки озвучка ждёт ▶, а другие плееры стоят до конца диктовки и её времени, потом продолжают через
«Пауза до и после речи». Флажок «Ставить другие плееры на паузу» снят - диктовка других плееров не трогает. Нужны `pactl` в PATH и PipeWire; нет
`pactl` или слежение оборвалось - одна строка WARNING, диктовка считается неидущей, плеер работает как обычно.
Не на Linux или без `pactl` слежение не запускается, а поле «Продолжать после диктовки через» скрыто.

## Тишина перед звуком

WirePlumber усыпляет устройство вывода через 5 с без звука (`session.suspend-timeout-seconds`
по умолчанию), и проснувшаяся Bluetooth-колонка съедает начало первого слова. Поэтому, если
вывод плеера молчал дольше 5 с, перед звуком идёт 0,5 с тишины: новое сообщение после паузы
в разговоре, ▶ после паузы, клик по строке, свой текст. Между предложениями одного сообщения
тишины нет. Простой общий для очереди и своего текста. Звуки других программ плеер не видит:
если колонку не дали усыпить они, тишина всё равно будет, только лишняя.

## Тесты

```bash
python3 -m unittest discover -s tests
```

Случаи с окном автоматически идут под `broadwayd`.

Тесты идут с `GIO_USE_VFS=local`: его ставит `tests/__init__.py` (каждый модуль тестов первой
строкой импортирует `tests`), поэтому они не касаются сессионной шины пользователя.

## Проверка вручную

```bash
python3 -m unittest discover -s tests
command -v tts-player tts-player-hook
# в сессии Claude Code:
# запустить новую сессию Claude Code: SessionStart - демон и плеер запущены, сессия в списке
# выйти из неё (или /clear): SessionEnd - сессия убрана из списка, её хуки молчат
# /resume: сессия снова в списке
```

- Начинать сессию заново ради проверки нельзя: `SessionEnd` удалит её тексты.
- `tts-player session has "$CLAUDE_CODE_SESSION_ID"; echo $?` - 0 после `SessionStart`, 1 после `SessionEnd`.
- Плеер стартует в трее с закрытым окном; чтобы открыть окно, щёлкните по значку в трее
  (`tts-player --show` показывает окно только при запуске нового экземпляра).
- Ошибки запуска плеера - в логах ниже.

## Логи

- `$XDG_RUNTIME_DIR/tts-player/player.log` - вывод плеера;
- `$XDG_RUNTIME_DIR/tts-player/hook.log` - хуки сессии;
- `~/.claude-tts/daemon-restart.log` - перезапуск демона из `install.sh`;
- `journalctl -t tts-player-sink` - сбои `tts-player sink` (на macOS - Console.app, поиск по `tts-player-sink`);
- `~/.claude-tts/daemon.log` - демон.
