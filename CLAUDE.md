# CLAUDE.md

## Проект — вайбкодинг для себя

Пользователь делает плеер для себя: код не читает, никуда его не публикует. Тесты, документация
(README, спеки, планы) и git — мои рабочие инструменты, а не то, что пользователь проверяет. Поэтому:

- Код, тесты, документацию и коммиты на проверку не выношу и разрешения на них не спрашиваю.
  Глобальные правила о незакоммиченных правках «на проверку» и об остановках для ревью здесь не действуют.
- Пользователь проверяет работу на запущенном плеере: что видно и слышно. Вопросы к нему — только о
  поведении плеера, теми словами, которые он видит в окне, а не об устройстве кода.

## По завершении правки — коммит и перезапуск плеера, без вопросов

Рабочее дерево `master` — живая установка плеера. Когда правка готова и тесты прошли:

1. Сразу закоммитить все изменения задачи: `git commit <пути> -m "…"`, сообщение по-русски, как в истории.
   Не оставлять правки в индексе «на проверку» и не спрашивать «закоммитить?».
2. Сразу перезапустить плеер, чтобы изменения было видно:

   ```bash
   pid=$(pgrep -f "python3 -m tts_player$"); kill $pid
   for i in $(seq 20); do kill -0 $pid 2>/dev/null || break; sleep 0.25; done
   cd ~ && setsid nohup ~/.local/bin/tts-player >/dev/null 2>&1 </dev/null &
   ps -eo pid,lstart,args | grep tts_player | grep -v grep
   ```

3. В отчёте — что сделано, хэш коммита и время перезапуска. Дурацких вопросов («перезапустить?»,
   «хотите другой вариант?») не задавать: пользователь смотрит в перезапущенном плеере, а исправления
   идут следующим коммитом.
